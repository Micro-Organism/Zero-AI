# 三轮微调复盘：问题记录与解决方案（v1 → v2 → v3）

> 目的：把「为什么还不满意」写死，避免下一轮再盲训。  
> 配套：`engineering_acceptance.md`（门禁）、`gate_suite.md`（固定题面）、`sample_alpaca_zh_v4.jsonl`（待训数据）。

---

## 1. 总览结论

| 轮次 | 解决了什么 | 没解决什么 | 教训 |
|------|------------|------------|------|
| **v1** | Kaggle QLoRA 链路、保存/推理 | 能力几乎未训出来（数据极小） | 先通链路，别把通链路当满意 |
| **v2** | 扩数据+加步后概念题变好 | 「落地建议」长套话污染产物题 | **坏模板会被学进去**；loss 低≠好 |
| **v3** | 去掉长套话（G4✓），G2 稳定 | G1 必留/可选仍错；G3 辨析不稳 | 去污染≠关键题学稳；稀疏监督不够 |

**当前工程状态：** G2✓ G4✓；G1✗ G3✗；G5 视本机是否已下载 v3。  
**不满意的主因：** 不是 r/lr 玄学，而是 **评测协议漂移 + 关键题监督过稀 + 短垫片抢结尾 + 从污染权重短续训**。

## 2. 已记录的问题清单（P）与解决方案（S）

### P1 · 用 loss 当满意度

- **现象：** v2 loss≈0.12 更低但产物更套话；v3 loss≈0.26 更高但 G4 更好。  
- **方案 S1：** 满意度只认 **Gate Suite 双采样全过**（见 `gate_suite.md`）。loss 只记日志。

### P2 · 「落地建议」长套话污染（v2 主伤）

- **现象：** 训练集约 55% output 被同一句垫长；模型复读模板。  
- **方案 S2：** 生成器禁止该句；v3 已清零。回归检查：`落地建议：把该知识点` 计数必须为 0。

### P3 · 短垫片换皮（v3 残留）

- **现象：** 「交付时至少能指出…」「工程习惯…」「面试表述…」仍占约 56% 样本；答案结尾鸡汤化。  
- **方案 S3：** v4 **默认不再 enrich 垫片**；短答以金标本身写够为准。开训前检查垫片率 ≈ 0。

### P4 · 产物题（G1）必留/可选边界错

- **现象：** 会列清单，但不稳定点名 `adapter_model` + `adapter_config`；甚至把适配器放进「可选」。  
- **根因：** 精确/近义金标只有个位数 / 521；句式不统一；续训 60 steps 压不过旧先验。  
- **方案 S4：** v4 产物簇 **≥40 条**，output **统一先写必留（适配器权重+adapter_config+日志超参+评测）再写可选（GGUF/merge/Hub）**；禁止「适配器」出现在可选。开训前脚本统计命中。

### P5 · QLoRA 辨析（G3）不稳定

- **现象：** 有时含糊「可能更新全部权重」；有时首句对后半糊。  
- **根因：** 评测原句「全部参数都以 4bit 做全量更新」在训练集命中 **0**；近义仅 1 条且措辞不同。  
- **方案 S5：** v4 写入 **≥20 条** 辨析簇，**必须含评测原句 + 多种改写**；output 骨架固定：`不等于。= 量化加载基座 + 只训 LoRA。≠ 全参 4bit 全量更新。`

### P6 · 评测协议漂移（假 Holdout 下标）

- **现象：** 口头「Holdout#0/#10/#25」与 `eval_holdout_zh.jsonl` 下标题面不一致；实际用的是看板固定 `ask()` 题。  
- **方案 S6：** 验收只用 `gate_suite.md` 里的**固定题面文本**；禁止再用漂浮 `#下标` 当唯一标识。

### P7 · 从 v2 短续训的残留先验

- **现象：** v3 去污染快，但 G1/G3 仍飘。  
- **方案 S7：** 最终满意版优先 **干净全量重训 v4**（基座+新 LoRA+补强数据）；若必须续训，则对产物/QLoRA 簇过采样，且仍以 Gate 双采样为准。

### P8 · 交付物未落盘（G5）

- **现象：** 本机 `outputs/` 可能仍无 `llama_lora_zh_v3/`。  
- **方案 S8：** 与模型能力无关；Download 适配器到本机并保留 Dataset 备份后再勾 G5。

### P9 · 关键题被「元问题」稀释

- **现象：** 「如何修复产物题」「评分要点」等教方法论的样本，和金标抢注意力。  
- **方案 S9：** 元问题可留极少量；金标簇数量级必须明显高于元问题。

### P10 · 轻易加 r / 只加 steps

- **现象：** 想靠容量或步数「碰」满意。  
- **方案 S10：** **禁止**在数据未过「开训前检查清单」时开训；禁止为 G1/G3 盲目提 r。

## 3. 开训前检查清单（v4 必须全绿）

在 Kaggle 开训前，本地跑 `02-data/check_v4_ready.py`（或看生成器打印），确认：

- [ ] `落地建议：把该知识点` 计数 = 0  
- [ ] 短垫片关键词命中率 ≈ 0（或 < 5%）  
- [ ] 产物相关 instruction ≥ 40  
- [ ] 训练数据含 Gate G1 **原句**  
- [ ] QLoRA 辨析簇 ≥ 20，且含 G3 **原句**  
- [ ] 与 Gate Suite 题面 **零 overlap 进 Holdout 即可，但原句必须在 train**  
- [ ] 已决定训练模式：推荐 `from_scratch` 出 `llama_lora_zh_v4`  
- [ ] v3 已本机留档（回滚）

全绿 → 才允许训一轮。训完 → Gate Suite **每题采样 2 次**全过 → 宣布满意并停手。

## 4. 「按这样做，下次一定满意吗？」

**不能保证 100%，但可以把「不满意」变成「可验收的高概率成功」。**

| 说法 | 是否成立 |
|------|----------|
| 再不改数据、再盲训一轮 | 大概率仍不满意 |
| 只做 v4 数据补强 + 开训前检查全绿 + 干净重训 + Gate 双采样 | **大概率能过 G1～G4**；G5 靠交付流程 |
| 数据检查没绿就开训 | 仍可能失败，且浪费配额 |

诚实预期：

1. **G2/G4** 已过，v4 主要打 G1/G3，目标清晰。  
2. 按 S4/S5 把原句与统一句式补进数据后，从机制上对准了失败模式。  
3. 仍存在采样随机性 → 所以要求 **双采样**；若一过一不过，只补失败簇 10～20 条再 **小步续训**，不要推倒重来改 r。  
4. 若 v4 全绿检查后仍双采样不过：问题会收窄到「句式冲突/过采样不足」，再迭代数据，而不是怀疑整条路线。

**一句话：按本文方案，「下一枪」是有工程把握的一枪；不是玄学碰运气。满意的充要条件是 Gate Suite 双采样全过，不是 loss。**

## 5. 推荐执行顺序（从现在到满意）

1. 阅读本文 + `gate_suite.md` + `engineering_acceptance.md`  
2. 生成本地 `datasets/sample_alpaca_zh_v4.jsonl`，跑检查脚本至全绿  
3. 上传 Kaggle Dataset（如 `zero-ds-v4`），**干净重训** → `llama_lora_zh_v4`  
4. Gate Suite 双采样打勾；过则停，不过则只补失败簇  
5. 本机归档 + 更新 `engineering_log.md` / 看板 Step 9
