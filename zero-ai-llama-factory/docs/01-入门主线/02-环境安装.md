# 02 · 环境安装

## 本章目标

弄清安装分几层、校验命令是什么、可选依赖各自干什么。  
**若本机无显卡/磁盘紧：本章以通读为主，不必实际安装**；实装放到云端（见 [13-无GPU与云端学习规划.md](../03-概念与工具/13-无GPU与云端学习规划.md)）。

## 核心概念

安装分两层：

1. **GPU 运行时**：NVIDIA 多为 CUDA；华为昇腾为 NPU（另见官方 multibackend）。
2. **Python 包**：clone 源码后 `pip install -e .`，再按需装 metrics / deepspeed / bitsandbytes 等。

官方推荐先确认 GPU 支持 CUDA，再装匹配的 CUDA Toolkit，最后装 LLaMA-Factory。

## Step by step

### Step 1：检查硬件与基础工具

```bash
# Linux 系统信息
uname -m && cat /etc/*release

# 编译器
gcc --version

# NVIDIA 驱动 / GPU（有 NVIDIA 时）
nvidia-smi
```

- 到 [CUDA GPUs](https://developer.nvidia.com/cuda-gpus) 确认卡是否支持 CUDA。
- 官方文档示例常用 **CUDA 12.2** 一类版本；以你机器驱动兼容性为准。

### Step 2：安装 / 确认 CUDA（Linux 摘要）

官方流程概要（细节以官方页为准）：

1. 下载对应 CUDA runfile（注意与系统、驱动匹配）。
2. 安装时若驱动已存在，可按文档建议谨慎处理 Driver 选项。
3. 完成后执行：

```bash
nvcc -V
```

能看到版本号即 Toolkit 侧基本 OK。

Windows：确认系统版本在官方支持列表内，安装 CUDA 后同样用 `nvcc -V` 校验；必要时检查环境变量。

### Step 3：准备 Python 环境

建议独立虚拟环境（venv / conda 均可），Python 版本以 LLaMA-Factory 当前 README 要求为准。

```bash
# 示例：venv
python -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
python -m pip install -U pip
```

### Step 4：安装 LLaMA-Factory

```bash
git clone --depth 1 https://github.com/hiyouga/LLaMA-Factory.git
cd LLaMA-Factory
pip install -e .
pip install -r requirements/metrics.txt
```

若依赖冲突，官方建议可尝试：

```bash
pip install --no-deps -e .
```

（此时需自行保证核心依赖如 `torch` 等已正确安装且与 CUDA 匹配。）

### Step 5：校验

```bash
llamafactory-cli version
```

能打印出版本信息即安装成功。

### Step 6：（可选）按需装 Extra

| 依赖方向 | 典型用途 |
|----------|----------|
| bitsandbytes / hqq / eetq / gptq / awq / aqlm | 量化与 QLoRA |
| deepspeed | 分布式与大模型显存优化 |
| vllm | 高速推理 |
| modelscope | 国内下载模型/数据 |
| swanlab / wandb 等 | 实验跟踪 |
| torch-npu | 昇腾设备 |

完整表见官方「Extra Dependency」。

**Windows 特别说明（官方）：**

- QLoRA：可能需要安装适配 Windows 的 bitsandbytes wheel。
- FlashAttention-2：使用社区提供的 Windows 预编译包，按 CUDA 版本选择。

## 检查点

**概念过关（当前）：**

- [ ] 能说出：CUDA/驱动 → Python 环境 → `pip install -e .` → `llamafactory-cli version` 这条链
- [ ] 知道 metrics / deepspeed / bitsandbytes / vllm 等属于「按需 Extra」
- [ ] 知道 Windows 上 QLoRA/FA2 可能要特殊 wheel

**实操过关（以后有机器时）：**

- [ ] `nvcc -V` 或至少 `nvidia-smi` 正常（GPU 场景）
- [ ] `llamafactory-cli version` 成功
- [ ] 虚拟环境已激活

## 常见坑

- **驱动与 CUDA Toolkit 版本拧巴**：`nvidia-smi` 里的 CUDA Version 是驱动上限，不等于已装的 `nvcc` 版本。
- **系统 Python 乱装**：务必用 venv/conda，避免污染系统包。
- **装了 CPU 版 torch**：训练极慢或无法用 GPU；用 `python -c "import torch; print(torch.cuda.is_available())"` 检查。
- **网络拉模型失败**：可改用 ModelScope、镜像，或预先下载到本地路径。
