# 03 · 数据准备

## 本章目标

理解 LLaMA-Factory 支持的数据格式；能准备一份自定义 Alpaca 数据，并在 `data/dataset_info.json`（官方文档亦写作 data_info）中正确注册。

> 说明：源码仓库里文件名通常是 `data/dataset_info.json`。WebUI 文档若写到 `data/data_info.json`，以你 clone 的仓库实际文件名为准。

## 核心概念

- **所有要用的数据集**（本地或在线）都应在 `dataset_info.json` 里有一条定义。
- 主流两种格式：**Alpaca**、**ShareGPT**（含 OpenAI messages 变体）。
- 不同训练阶段（SFT / 预训练 / 偏好 / KTO / 多模态）字段不同。

入门只掌握：**Alpaca 指令监督微调** 即可。

## Alpaca：SFT（必学）

单条字段：

| 字段 | 是否必填 | 含义 |
|------|----------|------|
| `instruction` | 必填 | 人类指令 |
| `input` | 选填 | 补充输入 |
| `output` | 必填 | 模型回答 |
| `system` | 选填 | 系统提示 |
| `history` | 选填 | 多轮历史 `[[问, 答], ...]` |

训练时人类侧输入一般为：`instruction` + `input` 拼接；`output` 为学习目标。多轮时 `history` 里的回答也会参与学习。

**最小单轮样例：**

```json
[
  {
    "instruction": "用一句话介绍光合作用。",
    "input": "",
    "output": "光合作用是绿色植物利用光能把二氧化碳和水转化成有机物并释放氧气的过程。"
  }
]
```

**`dataset_info.json` 注册示例：**

```json
"my_sft_zh": {
  "file_name": "my_sft_zh.json",
  "columns": {
    "prompt": "instruction",
    "query": "input",
    "response": "output",
    "system": "system",
    "history": "history"
  }
}
```

官方样例：https://github.com/hiyouga/LLaMA-Factory/blob/main/data/alpaca_zh_demo.json

## 其他 Alpaca 变体（知道即可）

| 用途 | 关键点 |
|------|--------|
| 预训练 | `[{"text": "..."}]`，columns 里 `prompt: text` |
| 偏好（DPO/ORPO/RM） | `chosen` / `rejected`，且 `ranking: true` |
| KTO | `output` + `kto_tag`（true/false） |
| 多模态 | 额外 `images` / `videos` / `audios`，数量须与文本占位标记一致 |

## ShareGPT（进阶）

- 对话放在 `conversations` 列表，角色如 `human` / `gpt` / `function_call` / `observation`。
- 注册时通常设 `"formatting": "sharegpt"`，`messages` 映射到 `conversations`。
- OpenAI 风格 `messages` + `role`/`content` 是 ShareGPT 的特殊情况，需配置 `tags`。

预训练 **不支持** ShareGPT 格式。

## 官方 demo 里常见的 `identity` 是什么？

很多示例 YAML 会写：

```yaml
dataset: identity,alpaca_en_demo
```

- `identity`：仓库自带的「自我认知 / 身份」类小数据集（让模型学「你是谁」一类问答），体积小，适合冒烟。
- 与 `alpaca_*_demo` 拼在一起：先验证流程，再谈效果。
- 概念期：知道「示例里为什么总出现它」即可；业务微调时再换成你的领域数据。

具体内容以 GitHub `data/` 与 `dataset_info.json` 中的注册为准。

## 数据质量原则（比格式更重要）

格式对了只能保证「能训」；质量决定「训了有没有用」。概念期记住这些检查清单：

| 原则 | 自问 |
|------|------|
| 任务对齐 | 这条样本是否反映上线后真实会问的问题？ |
| 答案可学 | `output` 是否清晰、正确、风格统一？ |
| 避免泄漏 | 评估用的 holdout 是否混进训练集？ |
| 去重与去噪 | 是否大量复制粘贴、空答案、乱码？ |
| 难度分布 | 是否全是特简单或特偏门？ |
| 安全与合规 | 是否含不该训练的隐私/违规内容？ |
| 量质平衡 | 宁要 200 条精品，不要 2 万条脏数据先污染直觉 |

纸面练习：为自己的假想业务写 10 条「好样本」+ 3 条「故意写坏的样本」，并注明坏在哪里。

## Step by step（自定义 SFT 数据）

1. 在 LLaMA-Factory 仓库的 `data/` 下新建例如 `my_sft_zh.json`。
2. 按 Alpaca 字段写至少几十～几百条高质量样本（学习阶段 demo 可先 20～50 条验证流程）。
3. 编辑 `data/dataset_info.json`，追加上面的 `my_sft_zh` 条目（注意 JSON 逗号）。
4. 训练或 WebUI 里数据集名称填：`my_sft_zh`（与 key 一致）。
5. （可选）先用仓库自带 `alpaca_zh_demo` / `identity` 跑通，再换自己的数据。

## 检查点

**概念过关：** 能手写样例 JSON + 注册片段（记事本即可，不必放进真实仓库）。  
**实操过关（以后）：** 注册进云端仓库并被训练读到。

- [ ] 能区分 Alpaca 与 ShareGPT
- [ ] 理解自定义 json 必须被 `dataset_info.json` 登记
- [ ] 字段名与 `columns` 映射一致（最常见翻车点）
- [ ] 知道多轮要靠 `history` 或 ShareGPT `conversations`
- [ ] 知道 `identity` 常见于官方示例冒烟
- [ ] 能说出至少 3 条数据质量检查原则

## 常见坑

- **忘了注册**：只放了 json 文件，没写 `dataset_info.json` → 训练找不到数据集。
- **columns 映射写错**：文件里叫 `instruction`，映射却写成别的名字。
- **JSON 语法错误**：缺逗号、多逗号、编码非 UTF-8。
- **空 `output`**：SFT 必填回答。
- **模板与数据语言/风格不匹配**：后面选 `template` 时再对齐模型。
