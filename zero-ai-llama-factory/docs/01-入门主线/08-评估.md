# 08 · 评估

## 本章目标

知道 LLaMA-Factory 里两类常见评估：通用能力基准（如 MMLU / C-Eval）与 NLG 生成质量（BLEU / ROUGE）；会改 YAML 跑一次。

## 核心概念

评估不是「看一眼 chat 感觉还行」的替代品，但入门阶段两者都要会：

| 类型 | 目的 | 典型入口 |
|------|------|----------|
| 通用能力 | 知识/选择题类基准 | `llamafactory-cli eval ...` |
| NLG | 生成文本与参考答案的重合度等 | `llamafactory-cli train` + `do_predict: true` |

主观体验仍建议保留：用第 07 章对话，抽查业务相关问题。

## 通用能力评估

```bash
llamafactory-cli eval examples/train_lora/llama3_lora_eval.yaml
```

配置思路示例：

```yaml
### model
model_name_or_path: meta-llama/Meta-Llama-3-8B-Instruct
adapter_name_or_path: saves/llama3-8b/lora/sft   # 可选

### method
finetuning_type: lora

### dataset
task: mmlu_test          # 或 ceval_validation, cmmlu_test
template: fewshot
lang: en
n_shot: 5

### output
save_dir: saves/llama3-8b/lora/eval

### eval
batch_size: 4
```

### 常用 Eval 参数

| 参数 | 含义 |
|------|------|
| `task` | `mmlu_test` / `ceval_validation` / `cmmlu_test` 等 |
| `task_dir` | 评估数据目录，默认 `evaluation` |
| `batch_size` | 每 GPU batch，默认 4 |
| `lang` | `en` / `zh` |
| `n_shot` | few-shot 条数，默认 5 |
| `save_dir` | 结果保存路径（已存在可能报错） |
| `download_mode` | 数据集下载/复用策略 |

## NLG 评估（BLEU / ROUGE）

```bash
llamafactory-cli train examples/extras/nlg_eval/llama3_lora_predict.yaml
```

关键点：`stage: sft`、`do_predict: true`、`predict_with_generate: true`，并指定 `eval_dataset`。

也可用更快的批量推理脚本先出预测，再自行算指标：

```bash
python scripts/vllm_infer.py \
  --model_name_or_path path_to_merged_model \
  --dataset alpaca_en_demo
```

## Step by step

1. 固定一个要评估的模型（基座 或 基座+adapter 或 merged）。
2. 先跑一个小任务或减小样本，确认命令与路径无通。
3. 再跑完整 `mmlu_test` / `ceval_validation` 等（耗时、要下载数据）。
4. 业务场景额外准备 **私有 holdout 集**：用对话或 NLG predict 看领域效果。
5. 把配置、分数、样例回答记到自己的实验笔记（可另建 `docs/实验记录/`，需要时再加）。

## 检查点

**概念过关（当前）：**

- [ ] 分得清「基准评估」与「NLG / 业务抽查」
- [ ] 知道改 `task`、`adapter_name_or_path`、`save_dir` 各自影响什么
- [ ] 知道微调后基准分不一定上升——要结合业务指标看

**实操过关（以后）：**

- [ ] 跑通一次 eval 或 predict，并保存结果目录

## 常见坑

- `save_dir` 已存在导致失败：换目录或先清理。
- 评估 `template` 与任务不匹配（通用能力常用 `fewshot`）。
- 只看 MMLU、不看业务样本，造成「分高不好用」或「分低其实好用」。
- 网络问题导致评估集下载失败。
