# 10 · 分布式与量化进阶（选读）

## 本章目标

建立两张地图：多卡/多机怎么训；量化在「训练」和「导出部署」分别扮演什么角色。细节以官方页与示例配置为准。

## 一、分布式训练地图

官方 Distributed 文档覆盖多种后端，入门只需记住分层：

```text
单机单卡  →  单机多卡（DDP）  →  DeepSpeed ZeRO / FSDP  →  多机 + Ray 等
```

| 方案 | 适用直觉 |
|------|----------|
| Native DDP | PyTorch 原生多卡并行，先从这个理解 |
| DeepSpeed | 通过 ZeRO 等切分优化器状态/梯度/参数，扛更大模型 |
| FSDP / FSDP2 | PyTorch 侧分片策略，另一条大规模路径 |
| Ray | 更偏集群调度与弹性作业 |

### 学习 Step by step

1. 单卡 LoRA 已稳定。
2. 同机两卡：`CUDA_VISIBLE_DEVICES=0,1`，用官方单机多卡示例跑通。
3. 仍 OOM 或要更大 batch：再读 DeepSpeed 配置文件示例（ZeRO stage 含义）。
4. 多机：先搞清节点通信、共享存储与启动命令，再上业务数据。

NPU 场景请走官方 multibackend，不要假设与 CUDA 命令完全一致。

## 二、量化地图

先分清两条线：

| 线 | 何时用 | 例子 |
|----|--------|------|
| 训练期量化 | 显存不够，边量化边 LoRA | QLoRA、bitsandbytes 4-bit 等 |
| 导出期量化（PTQ） | 合并后要压缩部署 | GPTQ、AWQ、AQLM… |

官方 Quantization 还会提到 QAT、HQQ、EETQ 等——查表用，不必一次记完。

### 与第 06 章的衔接（务必记住）

- **合并 LoRA**：用未量化基座，不要边合并边乱加 `quantization_bit`。
- **QLoRA**：训练配置里的量化；合并规则仍遵循官方警告。
- **GPTQ 导出**：在完整（或指定）模型上做 post-training 量化，需校准数据。

### 学习 Step by step

1. 单卡 LoRA OOM → 按官方 QLoRA 示例改一版，只改量化相关项。
2. 训练满意 → 按第 06 章 merge（若文档要求特定流程则跟官方）。
3. 部署要更小 → 单独做 GPTQ/AWQ 导出实验，对比速度与质量。

## 检查点

- [ ] 能画出「单卡 → 多卡 → DeepSpeed/FSDP」升级路径
- [ ] 能区分 QLoRA（训练）与 GPTQ（导出）
- [ ] 知道合并 LoRA 的量化禁忌

## 常见坑

- 多卡进程没起对，实际仍在单卡硬扛。
- DeepSpeed 配置与 batch/累积步数不匹配。
- 用已 GPTQ 的模型当 LoRA merge 基座。
- 校准数据质量差，量化后胡言乱语。
