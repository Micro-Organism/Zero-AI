# 09 · 调优算法与加速（进阶）

## 本章目标

知道除「普通 LoRA SFT」外还有哪些微调算法与加速开关；能按显存/效果做选择题，而不是一次全开。

## 核心概念：调优算法（怎么训）

官方 Advanced → Tuning algorithms 常见类别：

| 方法 | 一句话 | 入门建议 |
|------|--------|----------|
| Full | 更新全部参数，效果潜力大、显存贵 | 大卡/小模型再试 |
| Freeze | 只训部分层 | 折中方案 |
| LoRA | 低秩适配器，主流默认 | **优先** |
| LoRA+ / rsLoRA / DoRA / PiSSA 等 | LoRA 变体，改初始化或更新方式 | 基线 LoRA 不够再比 |
| GaLore / BAdam 等 | 偏全参场景的显存友好优化 | 走全参时再看 |

学习策略：

1. 先固定数据与评价，跑通 **LoRA**。
2. 只改一个变量（如 DoRA vs LoRA）做对比。
3. 把 YAML、分数、样例回答记下来。

## 核心概念：加速（怎么更快更省）

官方 Acceleration 常见项：

| 技术 | 作用直觉 |
|------|----------|
| FlashAttention-2 | 更快/更省显存的注意力实现 |
| Unsloth | 针对部分模型的训练加速方案（需按文档启用） |
| Liger Kernel | 另一类内核级加速选项 |

注意：加速依赖 **GPU 架构、CUDA、包版本**；Windows 上 FA2 / bitsandbytes 往往要特殊 wheel（见第 02 章）。

## Step by step（建议实验顺序）

1. 复制已跑通的 LoRA SFT YAML 作为基线 A。
2. 开启文档推荐的 FlashAttention（若环境支持）作为 A1，对比 step/s 与显存。
3. 若官方示例含 Unsloth 配置，再开一组 B，对比墙钟时间。
4. 算法向：仅当基线效果不够时，试 DoRA 或 LoRA+ 等同数据对比。
5. 阅读官方 Best Practices（如 GPT-OSS LoRA 三步案例）对照自己的流程。

## 检查点

- [ ] 能解释 Full / Freeze / LoRA 的显存与风险差异
- [ ] 知道加速选项可能装不上，不是训练失败的唯一原因
- [ ] 做对比实验时只改一个因素

## 常见坑

- 同时打开多个实验性算法，出问题无法归因。
- 硬件不支持仍强开 FA2。
- 把「训练更快」误当成「效果更好」。
