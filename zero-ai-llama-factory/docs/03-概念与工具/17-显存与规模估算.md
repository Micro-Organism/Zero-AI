# 17 · 显存与规模估算

## 本章目标

没有显卡也能建立数量级直觉：多大模型、哪种微调、大概需要什么量级显存；将来租卡时不盲目下 70B。

> 下列为 **经验数量级**，不是精确公式。实际还受序列长度、batch、优化器状态、框架开销影响。以能跑通为准。

## 先分清三块显存开销

训练时显存大致被这些吃掉：

1. **模型参数**（及可能的量化后权重）
2. **梯度 + 优化器状态**（全参时非常大；LoRA 时主要在可训小参数上）
3. **激活值**（跟 `cutoff_len`、batch、是否 checkpointing 强相关）

所以会出现：同样 7B，全参训不起，LoRA 可以，QLoRA 更省。

## 方法对比（直觉）

| 方法 | 显存压力 | 磁盘产物 | 入门建议 |
|------|----------|----------|----------|
| Full | 很高 | 全量权重大 | 有大显存或小模型再试 |
| Freeze | 中高 | 视解冻比例 | 折中 |
| LoRA | 中（相对友好） | adapter 小 | **默认** |
| QLoRA | 更低 | adapter 小 | 显存紧时 |

## 模型规模与显存（非常粗的球公园）

假设：指令微调、中等上下文、单卡、LoRA/QLoRA 常见设置——仅用于「租哪张卡」的初筛：

| 参数量级 | LoRA 粗感 | QLoRA 粗感 | 备注 |
|----------|-----------|------------|------|
| 1B～3B | 消费级也可试 | 更轻松 | 适合第一次云端 demo |
| 7B～8B | 常见 16GB～24GB 档常被选 | 12GB～16GB 也可能 | 入门最常见区间 |
| 13B～14B | 更吃显存，注意长度与 batch | 往往更依赖 QLoRA/深速 | |
| 32B+ / 70B | 多卡或强量化/分片 | 规划集群或大卡 | 概念期先别碰 |

推理（只 forward）通常比训练省；但长上下文、大 batch 生成仍可能 OOM。

## 磁盘空间也要估（和你当前痛点相关）

| 东西 | 量级直觉 |
|------|----------|
| LLaMA-Factory 源码 | 相对小 |
| Python 环境 + torch | 数 GB 起 |
| 7B～8B 基座权重 | 常见约十几 GB 量级（视精度/格式） |
| LoRA adapter | 往往数百 MB 级或更小（视 rank） |
| HF 缓存重复下载 | 一不小心成倍膨胀 |

**概念期策略：** 不下模型；将来云端只保留 **一个** 正在用的基座 + 当前 adapter。

## 调参杠杆（OOM 时先动谁）

优先级建议：

1. `per_device_train_batch_size` → 1  
2. 降低 `cutoff_len`  
3. 增大 `gradient_accumulation_steps`（保有效 batch）  
4. 换更小模型  
5. 改 QLoRA / 更深显存优化（DeepSpeed 等）  
6. 多卡分片（进阶）

## 纸面练习

假设你只有一张 **24GB** 卡，想做中文领域 SFT：

1. 优先选什么参数量级？LoRA 还是 QLoRA？
2. `cutoff_len` 先定 512、1024 还是 4096？为什么？
3. 若还 OOM，下一步三个动作是什么？

把答案写在笔记里，实操时再验证。
