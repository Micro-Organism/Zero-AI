# 19 · 训练效果诊断

## 本章目标

建立「出问题先归因」的清单：不靠本机跑实验，也能对常见现象给出合理下一步。将来实操时把本页当排障手册。

## 使用方法

1. 先锁定现象属于哪一类。  
2. 只改一个变量验证假设。  
3. 记入 [实验记录模板.md](../00-总览/实验记录模板.md)。

## 一、根本跑不起来

| 现象 | 优先怀疑 | 下一步 |
|------|----------|--------|
| 找不到数据集 | 未注册 / 名字不一致 / JSON 坏 | 查第 03 章、`dataset_info.json` |
| CUDA OOM | 序列太长 / batch 太大 / 模型太大 | 第 17 章杠杆顺序 |
| `template` 相关报错或怪输出 | 模板与模型不匹配 | 第 20 章 |
| 依赖 / 导入失败 | 环境不干净、可选包装了但没装对 | 第 02 章；云端重建 venv |
| 合并失败或效果诡异 | 用了量化基座合并 LoRA | 第 06 章硬规则 |

## 二、能跑，但 loss / 曲线不对

| 现象 | 优先怀疑 | 下一步 |
|------|----------|--------|
| loss 几乎不降 | lr 过小、数据太杂、训太少、模板错导致学错格式 | 对照官方示例 lr；检查若干条 tokenize 后直觉；略增 epoch 或检查数据 |
| loss 爆炸 / NaN | lr 过大、坏样本、精度问题 | 降 lr；清洗数据；核对 bf16/fp16 |
| 训练集 loss 很低，一聊就崩 | 过拟合或评估集泄漏；只会背训练句 | 降 epoch/rank；加持有抽查；看是否数据泄漏 |
| 曲线震荡剧烈 | batch 有效过小、数据噪声 | 加大累积步；洗数据 |

## 三、能聊，但「感觉没学到」

| 现象 | 优先怀疑 | 下一步 |
|------|----------|--------|
| 和基座几乎一样 | 没加载 adapter；训太弱；数据与问题分布不符 | 确认推理 YAML；增数据质量而非只增数量 |
| 会说训练套话、业务不会 | 数据全是通用 demo | 换领域数据；保 holdout |
| 格式乱、角色错 | `template` 错或多轮构造错 | 第 20、03 章 |
| 基准分升了业务更差 / 反之 | 优化目标错位 | 第 08 章：业务抽查优先 |

## 四、超参「先动谁」（SFT + LoRA 经验序）

在数据与 template 已确认无误的前提下：

```text
1. 先保证能稳定跑完（显存、路径、template）
2. 再调数据质量与样本是否对齐任务
3. 再动：epoch、learning_rate、lora_rank、cutoff_len
4. 最后才试算法变体（DoRA 等）或对齐阶段（DPO）
```

经验口诀：**数据 > 模板匹配 > 能跑通 > 微调超参 > 花式算法**。

## 五、纸面归因练习

情景：用 `identity,alpaca_zh_demo` 训完，业务问题全答非所问，但 loss 降得很漂亮。

写下你的 Top-3 假设与各自验证方法（不必真跑）。  
参考思路：数据与业务分布不符；推理未加载 adapter；过拟合 demo 套话；template 导致表面 loss 好看。

## 检查点

- [ ] 能把故障分到「跑不起来 / 曲线异常 / 能聊但没用」三类
- [ ] 能背出超参调整的大致优先级
- [ ] 同意「只改一个变量」再下结论
