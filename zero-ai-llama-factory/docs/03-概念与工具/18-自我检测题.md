## 简要参考答案（自检用）

1. 配置化/WebUI 微调多模型；支持 SFT 与多种对齐；可推理、评估、导出。  
2. 训练；评估与预测；对话；导出。  
3. 数据 → SFT(LoRA) → 保存 adapter →（可选 merge）→ 推理/评估。  
4. adapter 小、需配合基座；merged 独立完整，便于部署。  
5. 模型与环境占空间大；无 GPU 反馈差；概念与读配置可零成本练。  
6～7. 略（对照第 03 章字段）。  
8. 声明这是排序/偏好集；chosen 更好，rejected 更差。  
9. 简单指令用 Alpaca；复杂多角色/工具用 ShareGPT。  
10. 模板决定特殊 token 与角色格式；错则对话结构乱、效果差。  
11. 16。  
12. 如 lr/epoch/batch、dataset 训练采样、save/logging 策略等。  
13. 常缺优化器状态，难以严格 resume。  
14. 不能（按官方警告）；用未量化基座合并。  
15. model 路径、template；adapter 路径与 finetuning_type。  
16. 更高吞吐/更快批量推理。  
17. 通用知识/选择题能力 vs 生成与参考文本重合度。  
18. 基准分布≠业务分布；格式与语气需人工看。  
19. Full > LoRA > QLoRA（一般而言）。  
20. 训练期省显存边训；PTQ 多在部署前压缩已有模型。  
21. DPO 成对好坏；KTO 单条 + 正负标签。  
22. 降 batch→1；降 cutoff_len；加大累积或改 QLoRA/更小模型。  
23. 小规模身份/自我认知类冒烟数据，常与 demo 拼在一起验流程。  
24. 如：任务对齐、答案正确清晰、无评估泄漏、去重去噪、合规等（任列 3 条）。  
25. 数据与业务分布不符；推理未加载 adapter；过拟合 demo 套话 / template 问题。  
26. 模板决定对话包装格式；顺序：官方模型支持 → examples 同族 YAML → README，勿抄过时博客。
