## 六、技术栈全景（完善：要不要 Hugging Face？还需要什么？）

> 本节为追加完善，不替代上文；用于回答「要不要 HF、还缺哪些技术」。

### 6.1 结论先说

| 问题 | 答案 |
|------|------|
| **需要用到 Hugging Face 吗？** | **要。** 走 Unsloth / 开源 LLM 微调时，HF 几乎是默认上游：下载基座模型、拉公开数据集、（可选）上传微调产物。Unsloth 文档里模型名也常写作 `unsloth/llama-3.1-8b-unsloth-bnb-4bit` 这类 **HF 仓库路径**。 |
| **HF 等于微调框架吗？** | **不等于。** HF 主要是 **Hub（仓库）+ 一套 Python 库**（`transformers` / `datasets` / `peft` / `trl` 等）。真正帮你省显存、加速训练的是 **Unsloth（以及其封装的训练流程）**。 |
| **可以完全不用 HF 吗？** | 理论上可：模型文件全离线拷贝、数据集自己准备。实操学习阶段 **不划算**；门控模型（需同意协议）也通常要登录 HF。 |

参考：[Unsloth LLM 微调指南](https://unsloth.ai/docs/zh/kai-shi-shi-yong/fine-tuning-llms-guide.md)（模型命名、QLoRA、保存后可 push 到 HF Hub、部署到 Ollama/vLLM 等）。

### 6.2 Hugging Face 具体用在哪几步

```text
1) 注册 huggingface.co → 创建 Access Token
2) Notebook 里登录：huggingface-cli login 或环境变量 HF_TOKEN
3) 下载基座模型（transformers / unsloth FastLanguageModel.from_pretrained）
4) （可选）load_dataset("某公开数据集") 或自备 JSON 再转 Dataset
5) 训练（Unsloth + TRL SFTTrainer 等）
6) （可选）push_to_hub 上传 LoRA / 合并后模型，方便别处拉取
```

**你需要准备的 HF 相关事项：**

1. 账号（免费即可）  
2. Access Token：至少 **Read**；若要上传模型再开 **Write**  
3. 部分模型需在模型页点 **Agree and access**（门控协议）  
4. 网络能访问 `huggingface.co` / CDN（国内常需镜像或代理，需单独确认）
