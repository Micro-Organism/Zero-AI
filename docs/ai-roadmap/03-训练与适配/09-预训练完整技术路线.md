# 预训练完整技术路线

> 一句话定位：从合法语料、数据治理和 tokenizer 开始，通过自监督目标与分布式训练得到基础权重；学习阶段应以 tiny model 理解闭环，而不是盲目复刻工业规模。

## 快速概览

| 维度 | 预训练的本质 | 学习阶段的合理目标 |
|---|---|---|
| 输入 | 大规模、宽覆盖、经过治理的原始语料 | 可审计的小语料与数据报告 |
| 初始状态 | 随机权重，或在已有模型上继续预训练 | 从零 tiny model + 小规模继续预训练各一次 |
| 目标 | 从数据本身构造监督信号，如 next-token prediction | 理解 loss、packing、checkpoint 和 scaling 约束 |
| 资源 | 工业级通常需要多机多卡、存储与容错 | 单卡可完成最小教育实验 |
| 输出 | base model 权重、tokenizer、配置与训练记录 | 可复现 checkpoint、曲线和 model card |

## 学习地图（表格）

| Step | 主题 | 必须掌握 | 最低产出 |
|---:|---|---|---|
| 1 | 语料来源与合规 | 许可、隐私、版权、地域和保留策略 | source registry |
| 2 | 清洗与去重 | 解码、语言识别、质量规则、PII、近似去重 | 数据漏斗报告 |
| 3 | Tokenizer | BPE/WordPiece/Unigram、词表、特殊 token | 词表与 fertility 对比 |
| 4 | 数据构造 | shard、shuffle、packing、document boundary、mask | 可重复 dataloader |
| 5 | 训练目标 | causal LM、masked LM、denoising | 目标函数说明与单测 |
| 6 | 优化训练 | optimizer、scheduler、precision、gradient clipping | loss/吞吐/显存曲线 |
| 7 | 分布式与容错 | data/tensor/pipeline parallel、ZeRO/FSDP、checkpoint | 拓扑和恢复方案 |
| 8 | 评测与发布 | validation loss、下游评测、污染检查、model card | 基线对比与发布清单 |

## 核心技术要点与扩展谱系

| 层级 | 技术要点 | 解决的问题 | 前置知识 | 掌握标准 | 关联章节 |
|---|---|---|---|---|---|
| 必会 | corpus source、许可、PII、quality filter、dedup | 建立合法高质量训练分布 | 数据工程 | 能输出来源与数据漏斗 | `19`、`20` |
| 必会 | BPE/Unigram、vocabulary、normalization、fertility | 训练/选择 tokenizer | NLP | 能比较领域与多语言拆分 | `06`、`08` |
| 必会 | causal LM、masked LM、denoising、contrastive objective | 从数据自身构造监督信号 | 概率、Transformer | 能按架构解释 loss 与 mask | `08` |
| 必会 | shard/shuffle/packing/document boundary | 高效且正确地组织 token | DataLoader | 能验证边界和确定性恢复 | `05`、`19` |
| 必会 | AdamW、warmup/decay、effective batch、gradient clipping | 稳定大规模优化 | 优化、PyTorch | 能诊断 loss spike/NaN | `02`、`05` |
| 进阶 | scaling law、data mixture/curriculum、Chinchilla 类计算最优 | 配置参数、token 与算力 | 统计、预算 | 能解释预算下的数据/模型取舍 | `14`、`16` |
| 进阶 | DDP/FSDP/ZeRO、tensor/pipeline/context parallel | 扩展到多 GPU/长上下文 | 分布式训练 | 能说明各自切分对象 | `16` |
| 进阶 | MoE routing/load balance、expert parallel | 扩大稀疏模型容量 | Transformer、通信 | 能解释路由 loss 与 all-to-all | `08`、`16` |
| 进阶 | checkpoint、data cursor、fault tolerance | 从故障恢复一致训练 | 存储/分布式 | 能演练中断恢复且不跳样本 | `15-16` |

## 预训练、微调与迁移学习总对比

| 概念 | 起始权重 | 数据规模 | 训练目标 | 计算成本 | 输出产物 | 典型用途 |
|---|---|---|---|---|---|---|
| 从零预训练 | 随机初始化 | 最大，通常通用宽覆盖 | 自监督语言/视觉建模 | 最高 | 基础模型权重 + tokenizer | 建立全新基础模型或研究架构 |
| 继续预训练 | 已有基础模型 | 中到大，通常领域语料 | 延续自监督目标 | 高 | 领域适配后的基础模型 | 补充领域语言、知识和分布 |
| 监督微调/对齐 | 已有基础或指令模型 | 小到中，高质量任务/偏好数据 | 指令响应、任务损失或偏好目标 | 中到低 | 全量权重或 Adapter | 改变任务行为、格式、风格和偏好 |
| 迁移学习 | 任意预训练模型 | 通常小到中 | 下游任务目标 | 低到中 | 特征、任务头或适配后模型 | 将已有表示迁移到新任务/领域 |

## 纵向：从原理到交付的完整闭环

```text
能力与预算定义 -> 合法数据源登记 -> 下载/解析 -> 清洗/PII/去重
              -> tokenizer 训练/选择 -> shard/shuffle/packing
              -> 目标与模型配置 -> 小规模冒烟 -> 分布式训练/容错
              -> checkpoint -> validation/下游评测/污染检查
              -> model card/权重发布 -> 后训练与部署
```

| 环节 | 关键决策 | 主要风险 | 验收证据 |
|---|---|---|---|
| 数据源 | 来源、许可、配比、截止日期 | 版权、隐私、偏差 | source registry 与审批记录 |
| 数据治理 | 质量过滤、精确/近似去重、PII | 重复记忆、误删少数语言 | 规则版本、抽检与数据漏斗 |
| Tokenizer | 算法、词表、特殊 token、归一化 | 领域词碎片化、版本不兼容 | 多语言/领域 fertility 报告 |
| 数据加载 | packing、边界、shuffle、seed | 跨文档泄漏、样本重复 | deterministic smoke test |
| 优化 | batch、LR、warmup、precision | loss spike、溢出、训练不稳 | 曲线、梯度范数和异常告警 |
| 容错 | checkpoint 粒度、恢复、数据游标 | 重复/跳过数据、权重损坏 | 中断恢复演练 |
| 评测 | held-out loss、能力集、污染 | 测试集污染、只看平均分 | contamination audit 与分项结果 |

### 数据工程重点

1. **来源先于规模**：每个数据源记录 URL/所有者、许可证、抓取时间、允许用途与删除机制。
2. **清洗可解释**：HTML/编码修复、语言识别、长度与质量过滤都应版本化，并抽检误删/漏删。
3. **去重分层做**：精确 hash 去重解决完全重复，MinHash/LSH 等近似方法解决模板和转载；训练/评测之间还要交叉去重。
4. **敏感数据治理**：PII 检测、脱敏、访问权限和删除请求不能只依赖正则表达式。
5. **配比决定能力**：语言、代码、数学和领域数据的 sampling weight 会改变模型分布，必须记录而非口头约定。

### 训练系统重点

| 技术 | 解决的问题 | 学习顺序 |
|---|---|---|
| Mixed Precision | 降低显存并提高吞吐 | 先理解 FP32/FP16/BF16 与 loss scaling |
| Gradient Accumulation | 小显存模拟更大 effective batch | 明确 effective batch 计算 |
| Activation Checkpointing | 用重计算换激活显存 | 先测显存与吞吐取舍 |
| DDP/FSDP/ZeRO | 复制或切分模型状态 | 从 DDP 概念到参数/梯度/优化器分片 |
| Tensor/Pipeline Parallel | 单卡放不下模型时切层内或层间计算 | 后于数据并行学习 |

## 横向：与其他技术的连接

- **与数据工程**：预训练首先是数据供应链问题，包含对象存储、流式处理、schema、版本、血缘和质量监控。
- **与分布式系统**：通信、并行拓扑、故障恢复、checkpoint I/O 和集群调度共同决定有效训练时间。
- **与微调**：预训练产生 base model；SFT 和偏好对齐随后把基础能力塑造成可用行为。
- **与迁移学习**：继续预训练是一种领域适应；下游模型复用基础权重则是更广义的迁移学习。
- **与安全治理**：语料许可、隐私、污染与记忆风险必须在训练之前处理，发布后很难彻底修复。
- **与评测**：validation loss 只能说明预测分布，不能替代知识、推理、安全和下游任务评测。

## 技术对比与选型

### 训练目标对比

| 目标 | 输入/预测方式 | 优势 | 典型模型/用途 |
|---|---|---|---|
| Causal LM | 根据左侧 token 预测下一个 token | 与自回归生成一致、可扩展 | Decoder-only LLM |
| Masked LM | 预测被遮盖 token | 双向表示强 | BERT 类理解模型 |
| Denoising/Span Corruption | 从破坏后的输入恢复文本 | 适合 seq2seq 生成 | T5 类 Encoder-Decoder |
| Contrastive | 拉近正样本、推远负样本 | 表示与检索强 | Embedding、CLIP |

### 从零预训练与继续预训练

| 方案 | 何时选择 | 优势 | 代价/风险 |
|---|---|---|---|
| 从零预训练 | 新架构、新 tokenizer、特殊许可或大规模研究 | 控制完整数据和模型设计 | 成本极高，能力可能不及成熟底座 |
| 继续预训练 | 已有合适底座，需要领域语言/分布适配 | 复用能力，成本相对可控 | 灾难性遗忘、通用能力退化、许可继承 |
| 不做预训练 | 任务数据少、预算有限、知识可由 RAG 提供 | 最快进入业务验证 | 无法深度改变基础表示与领域分布 |

## Step by Step

1. 选择一个小型、许可清晰的文本集合，建立来源登记、数据 schema 和 held-out split。
2. 实现编码修复、质量过滤、语言统计、精确去重与 PII 抽检，输出每步保留率。
3. 训练一个小词表 BPE tokenizer，并与成熟 tokenizer 比较领域词拆分、平均 token 数和可逆性。
4. 将语料切成 shard，完成 shuffle、packing 与 document boundary 处理；为 data loader 写确定性测试。
5. 用 PyTorch 训练 tiny causal Transformer，先在极小 batch 上过拟合，确认 loss 和 mask 正确。
6. 加入验证、梯度裁剪、scheduler、mixed precision、checkpoint 与中断恢复。
7. 比较随机初始化 tiny model 与小规模继续预训练模型，观察收敛、领域 loss 和通用样例退化。
8. 输出 data card、model card、训练配置、资源消耗、评测结果和不适用边界。

## 最小项目与验收标准

**项目：可复现的领域 tiny language model 预训练实验**

| 验收项 | 过关标准 |
|---|---|
| 合规 | 每个数据源有许可、用途、时间和删除说明 |
| 数据 | 有清洗/去重/PII 漏斗，train/validation 交叉去重 |
| Tokenizer | 有 fertility、领域词和特殊 token 对比，版本固定 |
| 正确性 | tiny batch 可过拟合，causal mask 有自动测试 |
| 训练 | 可保存与恢复 checkpoint，恢复后数据游标和 loss 合理 |
| 评测 | 有 held-out loss、生成样例、领域/通用切片与污染说明 |
| 报告 | 记录 tokens、时长、峰值显存、吞吐、限制和复现命令 |

## 常见误区与面试达标

- 误区：把下载开源基础模型称为“完成预训练”。
- 误区：只追求 token 数，不记录语料许可、重复、配比和测试污染。
- 误区：看到训练 loss 下降就判断模型有效，忽略 held-out、下游能力和通用能力退化。
- 面试达标：能解释 tokenizer、causal LM、packing、effective batch、mixed precision 和 checkpoint 恢复。
- 面试达标：能说明为什么个人学习应训 tiny model，以及工业预训练的主要资源与风险在哪里。
