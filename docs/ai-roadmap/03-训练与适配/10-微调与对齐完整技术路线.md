# 微调与对齐完整技术路线

> 一句话定位：以明确任务和固定基线为起点，构造高质量指令/偏好数据，选择全量或 PEFT 训练，经过评测、合并、量化与部署，交付可复现且不破坏关键能力的模型版本。

## 快速概览

| 阶段 | 核心目标 | 典型技术 | 关键证据 |
|---|---|---|---|
| 基线 | 证明现有模型哪里不够 | Prompt、few-shot、RAG baseline | 固定测试集与错误分类 |
| SFT | 学习任务、格式、语气和对话模式 | Full FT、LoRA、QLoRA、DoRA | base vs tuned 对比 |
| 偏好对齐 | 在候选回答间学习人类/规则偏好 | DPO、KTO、ORPO、PPO/GRPO | win rate、安全与能力回归 |
| 交付 | 让适配结果可推理、可版本化 | merge、quantization、serving | 质量/延迟/显存报告 |

## 学习地图（表格）

| Step | 主题 | 必须掌握 | 最低产出 |
|---:|---|---|---|
| 1 | 任务与基线 | 目标、边界、失败 taxonomy、Prompt/RAG 基线 | baseline report |
| 2 | 指令数据 | instruction/input/output、质量、去重、切分 | dataset card |
| 3 | 模板与 tokenization | chat template、EOS、loss mask、truncation | token 可视化与单测 |
| 4 | SFT | loss、batch、LR、epoch、checkpoint | 可复现实验 |
| 5 | PEFT | LoRA target/rank/alpha/dropout、QLoRA | 显存/质量对比 |
| 6 | 偏好数据 | chosen/rejected、标注一致性、偏差 | preference audit |
| 7 | 对齐算法 | DPO/KTO/ORPO/PPO/GRPO 的前提和取舍 | 算法选型说明 |
| 8 | 评测与交付 | merge、量化、推理模板、服务回归 | release report |

## 核心技术要点与扩展谱系

| 层级 | 技术要点 | 解决的问题 | 前置知识 | 掌握标准 | 关联章节 |
|---|---|---|---|---|---|
| 必会 | instruction/chat/tool data、template、EOS、loss mask | 构造正确后训练监督 | tokenizer、数据工程 | 能解码抽检并测试 labels | `06`、`19` |
| 必会 | full fine-tuning、freeze/partial unfreeze | 选择参数更新范围 | PyTorch、迁移学习 | 能比较成本、适应和遗忘 | `11` |
| 必会 | LoRA：rank/alpha/target/dropout、adapter | 低秩参数高效更新 | 线代、Module | 能解释增量参数并做消融 | `02`、`05` |
| 必会 | QLoRA：4-bit base、NF4、double quant、paged optimizer 思想 | 降低大模型微调显存 | LoRA、量化 | 能区分存储量化和计算 dtype | `16` |
| 进阶 | AdaLoRA、DoRA、PiSSA、IA3/prefix tuning | 改进适配预算或参数化 | PEFT 基线 | 能在 LoRA 后做公平对比 | `11` |
| 进阶 | preference data、DPO/IPO/KTO/ORPO | 直接优化回答相对偏好 | SFT、概率 | 能解释 reference、beta 与偏差 | `14` |
| 进阶 | reward model、PPO/GRPO 类 online RL | 用反馈/奖励优化策略 | RL、rollout | 能识别 reward hacking 和成本 | `17`、`20` |
| 必会 | merge、adapter routing、quantization、serving template | 正确交付训练产物 | 推理部署 | 能逐阶段做质量回归 | `15-16` |
| 了解 | LLaMA Factory/Axolotl/Swift/Unsloth/torchtune | 端到端 recipe 与性能工具 | 底层方法 | 能映射配置到底层算法而非只会命令 | `05` |

## 预训练、微调与迁移学习总对比

| 概念 | 起始权重 | 数据规模 | 训练目标 | 计算成本 | 输出产物 | 典型用途 |
|---|---|---|---|---|---|---|
| 从零预训练 | 随机初始化 | 最大，通常通用宽覆盖 | 自监督语言/视觉建模 | 最高 | 基础模型权重 + tokenizer | 建立全新基础模型或研究架构 |
| 继续预训练 | 已有基础模型 | 中到大，通常领域语料 | 延续自监督目标 | 高 | 领域适配后的基础模型 | 补充领域语言、知识和分布 |
| 监督微调/对齐 | 已有基础或指令模型 | 小到中，高质量任务/偏好数据 | 指令响应、任务损失或偏好目标 | 中到低 | 全量权重或 Adapter | 改变任务行为、格式、风格和偏好 |
| 迁移学习 | 任意预训练模型 | 通常小到中 | 下游任务目标 | 低到中 | 特征、任务头或适配后模型 | 将已有表示迁移到新任务/领域 |

## 纵向：从原理到交付的完整闭环

```text
业务任务/风险 -> base/instruct 模型基线 -> 数据 schema/许可/切分
             -> chat template/tokenize/loss mask 检查
             -> Full FT 或 PEFT 冒烟 -> 训练/验证/checkpoint
             -> 任务/通用/安全/性能评测 -> 误差分析与数据迭代
             -> Adapter 保存或 merge -> 量化 -> 推理回归 -> 发布/监控/回滚
```

| 环节 | 必须回答 | 常见失败 | 验收证据 |
|---|---|---|---|
| 任务定义 | 要改变知识、行为、格式还是偏好 | 用微调解决实时知识问题 | 与 Prompt/RAG 的选型表 |
| 数据 | 来源、许可、质量、切分是否可靠 | 合成数据同质化、训测污染 | dataset card、去重报告 |
| 模板 | assistant loss 区域和 EOS 是否正确 | user token 也计损失、双模板 | 解码样本与 mask 单测 |
| 训练 | 哪个变量改变，如何复现 | 学习率过高、过拟合、错误 target module | config、曲线、checkpoint |
| 评测 | 目标能力提升是否牺牲通用/安全能力 | 只看训练 loss 或几条样例 | 多维回归矩阵 |
| 发布 | Adapter/merge/量化后的结果是否一致 | tokenizer/template 不匹配 | 发布前端到端回归 |

### 数据从原始样本到训练 token

```text
原始任务记录 -> 清洗/脱敏/去重 -> instruction schema
             -> train/validation/test 按来源或主体切分
             -> chat template -> tokenizer -> truncation/packing
             -> labels 与 loss mask -> 解码抽检 -> 训练
```

| 数据类型 | 结构 | 用途 | 主要风险 |
|---|---|---|---|
| 单轮指令 | instruction + optional input + output | 明确任务映射 | 指令过于模板化 |
| 多轮对话 | role/content messages | 对话状态与角色行为 | 截断丢上下文、角色泄漏 |
| 工具调用 | messages + tool schema/result | function calling | 参数不可执行、结果伪造 |
| 偏好对 | prompt + chosen + rejected | DPO 等偏好优化 | 长度偏差、标注不一致 |

### 训练监控矩阵

| 观察项 | 异常信号 | 优先排查 |
|---|---|---|
| train/validation loss | train 降、validation 升 | 过拟合、重复、切分污染 |
| token accuracy/格式成功率 | loss 降但格式不改善 | template、loss mask、评测解析 |
| 梯度范数 | spike、NaN/Inf | LR、精度、异常样本、clipping |
| 显存与吞吐 | OOM 或 tokens/s 降低 | sequence、packing、checkpointing、batch |
| 通用能力回归 | 目标任务升、基础能力降 | 数据配比、epoch、LR、遗忘 |

## 横向：与其他技术的连接

- **与预训练**：微调复用基础权重并使用更小、更有监督信号的数据；继续预训练仍用自监督目标，两者不可混称。
- **与迁移学习**：微调是迁移学习的一种实现；LoRA 只是参数高效的权重更新方式，不是独立学习范式。
- **与 RAG**：RAG 注入可更新事实，微调塑造稳定行为；生产系统可以同时使用二者。
- **与评测工程**：数据版本、base 基线、能力切片、安全集和性能回归决定微调结果能否可信发布。
- **与分布式/性能**：显存由权重、梯度、优化器和激活共同占用；QLoRA、checkpointing、ZeRO/FSDP 分别作用于不同部分。
- **与推理部署**：训练框架成功加载不代表推理成功；chat template、Adapter、merge、量化与 serving engine 都需端到端验证。

## 技术对比与选型

### 参数更新方式

| 方式 | 更新范围 | 显存/存储 | 优势 | 适合场景 |
|---|---|---|---|---|
| Full Fine-tuning | 全部参数 | 最高 | 适应能力强、无 Adapter 路径 | 数据/算力充足且域差大 |
| Freeze/Partial | 任务头或部分层 | 低到中 | 稳定、易理解 | 小数据、CV/Encoder 任务 |
| LoRA | 目标线性层低秩矩阵 | 低 | 成熟、Adapter 小、易切换 | 通用 LLM SFT 首选基线 |
| QLoRA | 量化底座 + LoRA | 更低 | 单卡可训练更大模型 | 显存紧张，接受速度/算子约束 |
| DoRA/PiSSA | 改进参数分解/初始化 | 近似 LoRA | 某些任务可能更优 | 在 LoRA 基线后做受控实验 |

### 偏好对齐方法

| 方法 | 数据/组件 | 优势 | 成本与限制 | 学习顺序 |
|---|---|---|---|---|
| DPO | chosen/rejected + reference 思想 | 流程比 PPO 简洁、常用 | 依赖偏好对质量和超参数 | 首个偏好基线 |
| KTO | desirable/undesirable 单样本 | 不强制成对数据 | 数据语义和实现需核实 | DPO 后按数据选择 |
| ORPO | SFT 与偏好目标结合 | 流程可简化 | 需验证任务稳定性 | 对比实验 |
| PPO | reward model + policy/value + rollout | 经典在线 RLHF | 系统复杂、成本高、不稳定 | 有充足基础后 |
| GRPO 类 | group relative reward/rollout | 推理任务上常见 | reward hacking 与采样成本 | 强化学习阶段深入 |

### 端到端框架对比

| 框架 | 核心定位 | 强项 | 主要取舍 | 优先场景 |
|---|---|---|---|---|
| LLaMA Factory | 一站式配置 + WebUI/CLI | 模型与训练范式广、中文资料多 | 抽象较高，仍需理解底层配置 | 入门、快速实验、多模型对比 |
| Unsloth | 单卡速度与显存优化 | QLoRA 快、消费级 GPU 友好 | 支持范围/多卡能力需按版本核实 | 单卡快速迭代 |
| Axolotl | YAML 驱动与可复现训练 | 配置工程、多卡生态成熟 | 学习配置与调试链路 | 团队实验和工程化 |
| ModelScope Swift | 国产模型与多模态工具链 | Qwen/中文生态、训练到部署 | 生态偏向 ModelScope | 中文/国产模型项目 |
| torchtune | PyTorch 原生训练 recipe | 代码透明、适合研究训练机制 | 开箱模型/功能广度相对集中 | 深入 PyTorch 训练循环 |

> 框架功能、许可证和商业版本变化快。选型前应以目标版本的官方仓库、文档和许可证为准，而不是长期记忆一张静态功能表。

## Step by Step

1. 明确任务、失败 taxonomy 和不可退化能力，固定 base/instruct 模型、Prompt 与 RAG 基线。
2. 建立数据 schema、来源/许可、质量 rubric、去重规则，并按主体/来源拆分 train/validation/test。
3. 应用模型官方 chat template，随机抽取样本检查 token、EOS、截断、labels 和 assistant loss mask。
4. 用 20-100 条样本做 overfit smoke test；无法过拟合时先修数据/训练链路。
5. 建立 LoRA 基线，再依据显存选择 QLoRA；一次只改变 rank、LR、epoch 等一个关键变量。
6. 在目标任务、通用能力、安全和格式四类固定回归集上比较 base 与 tuned。
7. 若确实需要偏好优化，先审计 chosen/rejected，再以 DPO 建立基线；不要直接跳到在线 RLHF。
8. 保存 Adapter 和训练配置；如需 merge/量化，逐阶段比较 logits 或任务指标并记录误差。
9. 在真实推理引擎中验证 chat template、并发、P95、显存、成本、敏感输入与回滚。

## 常见误区与面试达标

- 误区：训练 loss 下降就宣布成功，没有 base 对比、独立 test 和通用能力回归。
- 误区：把模型不会的实时事实都塞进 SFT 数据，忽略 RAG 更易更新和引用。
- 误区：使用错误 chat template、EOS 或 loss mask，模型仍能训练但学到错误目标。
- 误区：把 LoRA、QLoRA、DPO 和框架名称混在一个层级比较。
- 面试达标：能解释 Full FT、LoRA、QLoRA 的显存构成和选型依据。
- 面试达标：能从数据、模板、训练、评测、合并、量化到部署完整复盘一次实验。
