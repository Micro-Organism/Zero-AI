# 模型评测与算法工程化路线

> 一句话定位：把“模型感觉更好”转化为可复现的基线、指标、切片、误差归因、版本决策和线上反馈。

## 快速概览

| 层次 | 回答的问题 | 典型产物 |
|---|---|---|
| 数据质量 | 测试集可信且无污染吗 | dataset card、split/去重报告 |
| 能力评测 | 模型在哪些任务和切片更好 | metric matrix、置信区间 |
| 系统评测 | 延迟、吞吐、成本和稳定性怎样 | load test、SLO 报告 |
| 安全评测 | 是否泄露、越权或产生有害输出 | red-team set、风险登记 |
| 决策治理 | 是否值得发布，怎样回滚 | evaluation report、release gate |

## 学习地图（表格）

| Step | 主题 | 必做任务 |
|---:|---|---|
| 1 | 任务与 baseline | 定义业务目标、非 AI/base 模型基线 |
| 2 | 数据 split | 防泄漏、污染、重复和时间穿越 |
| 3 | 指标 | 分类/检索/生成/系统指标选型 |
| 4 | 切片与误差 taxonomy | 按长度、语言、领域、风险分解 |
| 5 | 统计可靠性 | bootstrap/置信区间、配对比较 |
| 6 | LLM-as-Judge/人工评测 | rubric、盲评、一致性、偏差校准 |
| 7 | 实验管理 | config/data/model/code 版本与 lineage |
| 8 | 在线评测 | A/B、监控、漂移、反馈和回滚 |

## 核心技术要点与扩展谱系

| 层级 | 技术要点 | 解决的问题 | 前置知识 | 掌握标准 | 关联章节 |
|---|---|---|---|---|---|
| 必会 | split、dedup/contamination、slice、golden set | 建立可信评测数据 | ML、数据工程 | 能证明测试独立且覆盖关键失败 | `03`、`19` |
| 必会 | classification/regression/ranking/generation metrics | 按任务选择度量 | 统计、任务定义 | 能解释指标与业务目标关系 | `03`、`06-07` |
| 必会 | baseline、ablation、paired comparison、bootstrap/CI | 判断改变是否真实有效 | 实验设计 | 能报告不确定性和唯一变量 | `02` |
| 必会 | error taxonomy、confusion/slice analysis、per-example result | 定位平均分背后的问题 | 指标 | 能把失败映射到数据/模型/系统 | 全部模型章节 |
| 进阶 | rule/program verifier、LLM-as-Judge、rubric、human eval | 评开放生成与执行任务 | LLM、标注 | 能校准 judge 偏差与一致性 | `08`、`12` |
| 进阶 | safety/red team、robustness/OOD、fairness/calibration | 衡量高风险与分布外行为 | 安全、统计 | 能建立风险切片和门禁 | `20` |
| 必会 | latency/throughput/error/cost、load test | 联合质量和系统性能决策 | 服务/性能 | 能给出 Pareto 与 SLO | `15-16` |
| 进阶 | online A/B、shadow/canary、drift/feedback | 在真实分布验证价值 | MLOps、统计 | 能定义 guardrail 和停止条件 | `15` |

## 纵向：从原理到交付的完整闭环

```text
业务目标 -> 风险与失败定义 -> 数据/切分 -> baseline -> 离线指标
        -> slice/误差分析 -> 受控实验 -> 统计比较 -> 发布门禁
        -> shadow/canary/A-B -> 在线 SLO/质量代理 -> 漂移/反馈 -> 回滚/迭代
```

| 阶段 | 必须固定 | 决策问题 |
|---|---|---|
| 实验前 | 假设、主指标、guardrail、数据版本 | 什么结果才算赢 |
| 实验中 | seed、config、代码、环境、checkpoint | 能否归因到唯一变量 |
| 实验后 | 完整结果、失败样本、成本 | 增益是否稳定且值得成本 |
| 发布前 | 回归集、SLO、安全阈值、回滚版本 | 是否满足发布门禁 |
| 发布后 | 版本、trace、输入/输出与反馈策略 | 真实分布是否退化 |

## 横向：与其他技术的连接

- **与 ML/DL**：数据泄漏、bias-variance、指标与消融是所有模型共同基础。
- **与微调**：base vs tuned 必须同一测试集与推理参数，同时检查目标和通用能力。
- **与 RAG/Agent**：分别评检索、生成、工具、轨迹与端到端成功率。
- **与 MLOps**：实验 tracking、registry、数据 lineage、canary 和 rollback 让评测结论可执行。
- **与产品**：离线指标是代理；线上任务成功、人工接管、投诉与成本才接近业务价值。
- **与安全**：高风险任务应按威胁模型建立专门测试集，而非只加一个“安全分数”。

## 技术对比与选型

### 评测方式

| 方式 | 优势 | 局限 | 使用原则 |
|---|---|---|---|
| 确定性指标 | 快、便宜、可回归 | 难覆盖开放生成质量 | 格式、分类、检索优先 |
| 规则/程序验证 | 可验证事实和执行结果 | 需任务可执行 | 代码、SQL、JSON、工具任务 |
| LLM-as-Judge | 可扩展开放回答评审 | 位置/长度/自偏好偏差 | rubric + 校准 + 抽检 |
| 人工评测 | 接近真实偏好 | 贵、慢、一致性问题 | 高价值样本、最终校准 |
| 在线 A/B | 真实业务效果 | 风险高、归因复杂 | 离线门禁后小流量进行 |

### 指标选型

| 任务 | 主指标候选 | 必须补充 |
|---|---|---|
| 不平衡分类 | Macro-F1、PR-AUC | confusion matrix、类别 slice |
| 检索/排序 | Recall@K、MRR、nDCG | latency、无答案 query |
| 生成 | task success、事实/引用、rubric | 格式、安全、人工抽检 |
| Agent | completion rate、tool success | steps、重试、越权、成本 |
| 服务 | P50/P95/P99、throughput、error | GPU/Token 成本、SLO |

## Step by Step

1. 写一页 evaluation spec：用户、任务、失败、主指标、guardrail 和发布阈值。
2. 建立 train/validation/test 和独立回归集，执行重复、污染和时间泄漏检查。
3. 跑最简单 baseline，保存逐样本结果而不只保存平均分。
4. 建立错误 taxonomy 与关键 slice，按样本定位模型退化。
5. 为生成任务设计 rubric，比较规则、LLM judge 和人工评分一致性。
6. 每次实验只改变一个主要变量，记录 config/data/code/model lineage。
7. 用 bootstrap 或配对检验报告不确定性，避免追逐微小随机波动。
8. 建立发布门禁、shadow/canary、监控阈值和一键回滚。

## 最小项目与验收标准

**项目：统一 AI Evaluation Harness 与模型对比报告**

| 验收项 | 过关标准 |
|---|---|
| 数据 | 版本、来源、污染检查和冻结策略明确 |
| 基线 | 至少比较两个模型/方案，逐样本结果可追溯 |
| 指标 | 主指标、guardrail、slice 与置信区间完整 |
| 生成评测 | judge rubric 经人工样本校准，记录偏差 |
| 系统 | 同时报告质量、P95、吞吐和成本 |
| 决策 | 有发布/不发布结论、限制和回滚条件 |

## 常见误区与面试达标

- 误区：测试集参与 Prompt/数据调优，最后仍称为独立评测。
- 误区：只报平均分，不报样本、切片、不确定性和成本。
- 误区：把 LLM-as-Judge 当真值，不校准偏差与一致性。
- 面试达标：能为分类、检索、生成和 Agent 分别设计指标与数据切分。
- 面试达标：能从一次指标变化追溯到数据、代码、配置和模型版本。
