# AI 安全与治理路线

> 一句话定位：从数据、模型、供应链、Prompt/RAG、Agent 工具到线上服务建立威胁模型、测试、权限、审计和事件响应。

## 快速概览
| 边界 | 典型风险 | 核心控制 |
|---|---|---|
| 数据 | PII、版权、投毒、偏见 | 来源、最小化、清洗、访问控制 |
| 模型 | 记忆泄露、越狱、有害输出 | 安全评测、过滤、能力限制 |
| RAG | prompt injection、越权检索 | ACL 过滤、不信任内容、引用 |
| Agent | 工具滥用、不可逆操作 | 最小权限、审批、幂等、预算 |
| 供应链 | 恶意权重/依赖/镜像 | 校验、扫描、隔离、SBOM |

| Step | 主题 | 必做任务 |

| 3 | 模型安全 | jailbreak、extraction、membership 风险 |

## 核心技术要点与扩展谱系

| 层级 | 技术要点 | 解决的问题 | 前置知识 | 掌握标准 | 关联章节 |
|---|---|---|---|---|---|
| 必会 | asset/data-flow/trust-boundary threat modeling | 系统化发现攻击面 | 架构图、数据流 | 能列资产、攻击者、路径、影响和控制 | `12`、`15` |
| 必会 | privacy/PII、consent、minimization、retention/deletion | 合法最小化处理数据 | 数据治理 | 能执行访问和删除流程 | `19` |
| 必会 | prompt/indirect injection、jailbreak、data exfiltration | 防止不可信内容控制系统 | LLM/RAG | 能构建攻击集并分层防御 | `08`、`12` |
| 必会 | least privilege、ACL、sandbox、approval、audit | 限制 Agent 和工具真实影响 | 后端安全 | 写操作可授权、撤权和追责 | `12`、`15` |
| 进阶 | poisoning/backdoor、model extraction/inversion/membership | 保护训练供应链和模型隐私 | ML、安全 | 能解释威胁前提与检测限制 | `09-10` |
| 必会 | hash/signature、dependency/image scan、SBOM、secret management | 控制模型与软件供应链 | DevSecOps | artifact 来源可验证且密钥不入库 | `15` |
| 必会 | red team、risk-based eval、release gate、incident response | 发布前测试和出事后恢复 | 评测/MLOps | 能演练阻断、熔断、回滚和复盘 | `14-15` |
| 进阶 | fairness、transparency、human oversight、model/system card | 管理社会和决策风险 | 统计、产品 | 能按群体/场景报告并明确责任人 | `14` |

## 纵向：从原理到交付的完整闭环
```text
资产/业务影响 -> 数据流与信任边界 -> 威胁/滥用案例 -> 风险分级
             -> 预防控制 -> 安全测试 -> 发布门禁 -> 监控/审计
             -> 事件隔离/回滚/通知 -> 根因与回归集
```
| 阶段 | 证据 | 失败动作 |
|---|---|---|
| 设计 | threat model、权限矩阵 | 降低能力/缩小范围 |
| 数据 | 来源、许可、PII 记录 | 隔离或删除数据 |
| 测试 | 安全集、攻击 trace | 阻止发布 |
| 运行 | 审计日志、异常指标 | 熔断、撤权、回滚 |
| 复盘 | timeline、根因、修复 | 加入永久回归 |

## 横向：与其他技术的连接
- **与数据工程**：数据最小化、血缘和删除能力是治理基础。
- **与微调**：训练数据可能投毒或泄漏；对齐不能替代运行时权限。
- **与 RAG/Agent**：内容是数据，不是可信命令；工具执行必须由业务系统再鉴权。
- **与 MLOps**：模型、Prompt、索引、工具 schema 都要版本化和回滚。
- **与产品**：按影响区分低风险建议与高风险自动决策，引入人工复核。

## 技术对比与选型
| 控制 | 解决 | 优势 | 局限 |
|---|---|---|---|
| 输入/输出过滤 | 已知模式 | 快、可审计 | 可绕过、误杀 |
| System Prompt | 行为提示 | 成本低 | 不是安全边界 |
| 模型对齐 | 降低有害倾向 | 改善默认行为 | 不保证权限与事实 |
| 沙箱/最小权限 | 限制真实影响 | 强边界 | 增加系统设计成本 |
| 人工审批 | 高风险操作 | 责任清晰 | 延迟和运营成本 |

### 治理与责任矩阵

| 治理维度 | 发布前问题 | 运行中证据 |
|---|---|---|
| 隐私 | 是否最小化收集、获得授权并支持删除 | 访问/删除日志、泄露告警 |
| 公平与偏差 | 哪些群体/语言/场景可能系统性退化 | 分组指标、申诉与人工复核 |
| 透明度 | 用户是否知道在与 AI 交互及其限制 | 披露、引用、model/system card |
| 人类监督 | 哪些决策禁止完全自动化 | 审批记录、人工接管率 |
| 责任归属 | 谁批准数据、模型、工具权限和发布 | owner、审批链、变更审计 |
| 第三方风险 | 基座模型/API/依赖的许可与数据边界 | 供应商版本、SLA、退出方案 |

法规和行业要求随地区与场景变化，本路线不把某一法规清单当通用答案。项目必须记录适用地区、数据类型、决策影响和责任人，并让法务、安全、隐私或行业专家参与高风险发布。

## Step by Step
1. 为一个 RAG/Agent 服务画数据流与信任边界。
2. 列出资产、攻击者、滥用案例、影响和已有控制。
3. 建立 prompt injection、越权、PII、工具滥用与 DoS 测试集。
4. 为检索实施用户级 ACL，禁止跨租户结果进入上下文。
5. 为写操作加入最小权限、参数校验、幂等和人工审批。
6. 校验模型/数据 hash，扫描依赖和容器，以非 root 运行。
7. 将安全阈值加入发布门禁并演练撤权、熔断和回滚。
8. 写事件响应 runbook 与 model/system card。

## 最小项目与验收标准
**项目：AI 助手安全评估与加固报告**
| 验收项 | 过关标准 |
|---|---|
| 模型 | 资产、边界、攻击路径和风险等级清楚 |
| 数据 | PII、许可、ACL、保留/删除可审计 |
| Agent | 最小权限、审批、预算、审计和补偿 |
| 测试 | 攻击集可重复，修复前后有回归 |
| 运营 | 告警、撤权、熔断、回滚和通知演练 |

## 常见误区与面试达标
- 误区：把 system prompt 当权限系统，把对齐模型当绝对安全。
- 误区：只防用户直接注入，不防文档和工具结果中的间接注入。
- 面试达标：能用信任边界解释纵深防御，并给出事件响应流程。
