# 分布式训练与性能优化路线

> 一句话定位：先测量显存、计算、通信、I/O 与推理延迟瓶颈，再选择精度、重计算、分片、并行或推理引擎优化。

## 快速概览

| 瓶颈 | 常见信号 | 主要手段 | 关键取舍 |
|---|---|---|---|
| 权重/状态显存 | 加载或 optimizer OOM | 量化、ZeRO/FSDP、PEFT | 精度、通信 |
| 激活显存 | 长序列/大 batch OOM | checkpointing、FlashAttention | 重计算、兼容性 |
| 计算 | GPU 高利用但慢 | mixed precision、kernel fusion、compile | 数值稳定、编译成本 |
| 通信 | 多卡扩展效率差 | bucket、拓扑、并行策略 | 同步与复杂度 |
| 数据/I/O | GPU 等数据 | prefetch、pin memory、shard/cache | CPU/存储占用 |
| 推理 | TTFT/TPOT/P95 高 | continuous batching、KV cache、quantization | 延迟、吞吐、质量 |

| Step | 主题 | 必做测量 |
|---:|---|---|
| 1 | GPU/显存基础 | allocated/reserved、利用率、tokens/s |
| 2 | Precision | FP32/FP16/BF16 的速度、显存和稳定性 |
| 3 | Batch/Sequence | micro/effective batch、长度分布 |
| 4 | 显存优化 | accumulation、checkpointing、PEFT/quantization |
| 5 | 单机多卡 | DDP、通信与 scaling efficiency |
| 6 | 状态分片 | ZeRO/FSDP 的参数/梯度/optimizer 分片 |
| 7 | 模型并行 | tensor/pipeline/context parallel 适用条件 |
| 8 | 推理优化 | TTFT、TPOT、throughput、KV cache、vLLM 类引擎 |

## 核心技术要点与扩展谱系

| 层级 | 技术要点 | 解决的问题 | 前置知识 | 掌握标准 | 关联章节 |
|---|---|---|---|---|---|

| 必会 | FP32/FP16/BF16、AMP/loss scaling | 降显存和提升 tensor core 吞吐 | 数值范围 | 能检查 NaN 与质量差异 | `05` |
| 必会 | micro/effective batch、gradient accumulation/checkpointing | 在显存约束下训练 | 反向传播 | 能计算 batch 并量化重计算代价 | `09-10` |

## 纵向：从原理到交付的完整闭环

```text
固定质量基线/工作负载 -> profiler + 显存分解 -> 定位最大瓶颈
                     -> 一次一个优化 -> 质量/速度/显存对比
                     -> 单卡稳定 -> 多卡 scaling -> 故障恢复
                     -> 目标硬件压测 -> 容量规划 -> 监控与回归
```

| 阶段 | 指标 | 通过条件 |
|---|---|---|
| 正确性 | loss/logits/任务指标 | 优化前后在容忍范围内 |
| 单卡训练 | tokens/s、峰值显存、step time | 可解释瓶颈与增益 |
| 多卡训练 | speedup、scaling efficiency、通信占比 | 增卡有合理收益 |
| 推理 | TTFT、TPOT、P95、吞吐、显存 | 目标并发下满足 SLO |
| 成本 | GPU-hour、tokens/second、每请求费用 | 增益值得复杂度 |

### 显存构成

```text
训练显存 ≈ 权重 + 梯度 + 优化器状态 + 激活 + 临时 buffer + 通信开销
推理显存 ≈ 权重 + KV Cache + 激活/临时 buffer + engine 预留
```

先区分是哪一部分超限：QLoRA 主要压缩底座权重，LoRA 降低可训练参数；activation checkpointing 主要减少激活；ZeRO/FSDP 分片模型状态；缩短序列和降低并发直接减少激活或 KV Cache。

## 横向：与其他技术的连接

- **与 PyTorch**：autocast、GradScaler、DDP、profiler、compile 与 DataLoader 是性能入口。
- **与微调**：LoRA/QLoRA、packing、gradient accumulation 和 checkpointing 决定单卡可行性。
- **与预训练**：多机训练还需要调度、容错、数据游标和分布式 checkpoint。
- **与部署**：训练吞吐和在线 serving 指标不同；在线要同时优化 TTFT、TPOT、并发和尾延迟。
- **与硬件**：显存带宽、计算能力、互联拓扑和存储决定最优策略，不存在通用“最快参数”。
- **与评测**：量化、kernel 和引擎变化都必须经过质量回归，不能只看速度。

## 技术对比与选型

### 分布式策略

| 策略 | 切分对象 | 何时用 | 主要代价 |
|---|---|---|---|
| DDP | 数据，模型每卡复制 | 模型单卡放得下 | 状态显存重复 |
| ZeRO/FSDP | optimizer/梯度/参数 | 模型状态单卡压力大 | 通信与配置复杂 |
| Tensor Parallel | 单层张量计算 | 单层/模型单卡放不下 | 依赖高速互联 |
| Pipeline Parallel | 不同层/阶段 | 模型很深、跨设备 | pipeline bubble、调度 |
| Context/Sequence Parallel | 长序列维度 | 超长上下文 | 算子和通信复杂 |

### 优化手段

| 技术 | 节省/加速对象 | 代价 |
|---|---|---|
| Mixed Precision | 权重/激活带宽与计算 | 溢出、精度差异 |
| Gradient Accumulation | micro-batch 显存 | step 更慢，不等于并行 |
| Activation Checkpointing | 激活显存 | 反向重计算 |
| FlashAttention | Attention I/O/显存 | 硬件、dtype、版本兼容 |
| Quantization | 权重/KV/计算 | 质量、校准、kernel 支持 |
| Continuous Batching | 推理 GPU 利用率 | 调度、尾延迟管理 |

## Step by Step

1. 固定模型、数据、seed、batch/sequence 与质量基线，记录硬件和软件版本。
2. 用 profiler 和 GPU 指标拆分 data、forward、backward、optimizer、communication 时间。
3. 比较 FP32/BF16/FP16，检查 NaN、梯度范数和最终指标。
4. 分别测试 accumulation、checkpointing、packing 和 FlashAttention，每次只改一个变量。
5. 用 DDP 做 1/2/4 卡扩展，计算 speedup 和 scaling efficiency。
6. 模型状态放不下时再比较 FSDP/ZeRO；记录 checkpoint 保存与恢复。
7. 为推理测不同输入/输出长度和并发下 TTFT、TPOT、P95、吞吐与显存。
8. 比较 eager/HF 与 vLLM 类引擎、量化版本，提交质量-延迟-成本 Pareto 报告。

## 最小项目与验收标准

**项目：训练与推理性能基准报告**

| 验收项 | 过关标准 |
|---|---|
| 基准 | 工作负载、硬件、版本和质量指标固定 |
| Profiling | 能定位主要时间和显存构成 |
| 训练 | 至少三种优化有独立消融和稳定性结果 |
| 多卡 | 报告 speedup、效率、通信占比和恢复测试 |
| 推理 | 按长度/并发报告 TTFT、TPOT、P95、吞吐 |
| 决策 | 给出质量-显存-速度-成本与复杂度取舍 |

## 常见误区与面试达标

- 误区：OOM 就机械减 batch，不判断权重、状态、激活还是 KV Cache。
- 误区：只报峰值吞吐，不报质量、尾延迟和真实长度分布。
- 误区：多卡能运行就算扩展成功，不计算 scaling efficiency。
- 面试达标：能解释 DDP、FSDP/ZeRO、tensor/pipeline parallel 的切分对象。
- 面试达标：能解释 TTFT、TPOT、KV Cache 和 continuous batching。
