# 大模型与生成式 AI 路线

> 一句话定位：理解大模型如何把文本转换为 token、通过 Transformer 建模并逐 token 生成，再把模型能力连接到训练、微调、RAG、Agent、评测与部署。

## 快速概览

| 层次 | 核心问题 | 必须掌握的技术 | 最低学习证据 |
|---|---|---|---|
| 表示 | 文本怎样进入模型 | tokenizer、vocabulary、embedding、position encoding | 比较两种 tokenizer 的长度与成本 |
| 模型 | token 怎样交换信息 | Transformer、Attention、MLP、Residual、Norm | 手算并实现一次 masked attention |
| 生成 | 下一个 token 怎样产生 | logits、softmax、temperature、top-k/top-p、KV Cache | 比较解码参数的质量、稳定性和延迟 |
| 适配 | 通用模型怎样解决具体任务 | Prompt、RAG、SFT、PEFT、偏好对齐 | 为同一任务建立至少两种方案基线 |
| 交付 | 模型怎样成为可靠系统 | evaluation、serving、quantization、guardrail、monitoring | 有回归集、延迟/成本指标和失败分析 |

## 学习地图（表格）

| Step | 主题 | 关键问题 | 必做实验 |
|---:|---|---|---|
| 1 | Tokenizer 与 Embedding | token 不等于字或词，词表怎样影响长度与语义 | 对中英、代码和数字文本做分词统计 |
| 2 | Transformer | Q/K/V、Mask、Residual、Norm、MLP 怎样协作 | 实现小型 causal self-attention |
| 3 | 预训练目标 | next-token prediction 学到了什么 | 用 tiny corpus 训练字符或 BPE 小模型 |
| 4 | 自回归生成 | greedy、beam、sampling 有何差异 | 固定 prompt 比较 temperature/top-p |
| 5 | 上下文与推理 | context window、KV Cache、batch 怎样影响资源 | 测量输入/输出长度与显存、延迟关系 |
| 6 | 能力适配 | Prompt、RAG、微调分别改变什么 | 同一知识任务做 Prompt/RAG 对比 |
| 7 | 评测与安全 | “回答看起来不错”为什么不够 | 建立正确性、格式、拒答和安全回归集 |
| 8 | 工程交付 | 模型如何部署、监控、降级与回滚 | 包装 API 并记录 P50/P95、成本和错误率 |

## 核心技术要点与扩展谱系

| 层级 | 技术要点 | 解决的问题 | 前置知识 | 掌握标准 | 关联章节 |
|---|---|---|---|---|---|
| 必会 | BPE/WordPiece/Unigram、vocabulary、special token | 将输入变成稳定离散单元 | NLP、字符串 | 能比较 fertility、长度和成本 | `06`、`09` |
| 必会 | Transformer block、MHA/GQA/MQA、MLP、Residual、RMSNorm | 建模 token 依赖 | Attention、矩阵 | 能跟踪 shape 与参数/计算量 | `04-05` |
| 必会 | positional encoding、RoPE、causal/padding mask | 表示顺序并控制可见范围 | 三角矩阵 | 能验证未来 token 不可见 | `09` |
| 必会 | autoregressive decoding、greedy/beam/top-k/top-p/temperature | 从分布产生序列 | softmax、概率 | 能比较质量、随机性和复现 | `14` |
| 必会 | context window、KV Cache、prefill/decode、TTFT/TPOT | 理解长输入与推理资源 | Transformer | 能测长度/并发对显存延迟影响 | `16` |
| 进阶 | instruction tuning、RAG、tool calling、structured output | 让模型适配任务、知识和行动 | LLM 推理 | 能区分 Prompt/RAG/微调/Agent | `10`、`12` |
| 进阶 | MoE、routing、load balancing、dense vs sparse | 扩大参数容量而控制单 token 计算 | Transformer/分布式 | 能解释激活参数和通信代价 | `09`、`16` |
| 进阶 | long-context：RoPE scaling、sliding/window/sparse attention | 扩展可处理序列 | 位置编码、Attention | 能区分窗口长度与有效利用能力 | `09`、`14` |
| 进阶 | State Space Model：S4/Mamba 类 | 用状态递推和选择性扫描高效建模长序列 | RNN、卷积、线性系统直觉 | 能比较 RNN、Transformer 与 SSM 的复杂度和并行性 | `04`、`23` |
| 了解 | CoT/self-consistency、speculative decoding、reasoning model | 改善推理路径或生成速度 | 解码、评测 | 能识别质量增益、成本和不可验证性 | `14`、`16` |
| 了解 | VAE/GAN、Diffusion、Flow Matching、codec/token model | 文本外生成模型家族 | 概率、DL | 能比较生成目标与采样机制 | `13`、`24` |

## 纵向：从原理到交付的完整闭环

```text
任务/风险定义 -> 数据与合规 -> tokenizer/模型选择 -> Prompt 或训练基线
             -> 离线评测 -> 误差归因 -> RAG/微调/对齐迭代
             -> 量化与推理服务 -> 在线监控 -> 降级/回滚 -> 数据飞轮
```

| 环节 | 应回答的问题 | 典型产物 |
|---|---|---|
| 问题定义 | 任务需要知识、行为、格式，还是推理能力 | 任务说明、非 LLM 基线、风险分级 |
| 数据 | 来源是否合法，是否含隐私、重复、污染和偏见 | data card、schema、数据版本 |
| 模型选择 | 参数量、语言、许可证、上下文和硬件是否匹配 | model card 对比、资源预算 |
| 适配 | Prompt/RAG/微调哪一种最小可行 | 基线矩阵、实验配置 |
| 评测 | 正确性、事实性、安全、延迟和成本如何衡量 | 固定回归集、评分 rubric、报告 |
| 部署 | 并发、超时、缓存、降级和版本如何管理 | API、监控面板、回滚方案 |

### 必须讲清的核心机制

1. **Tokenization**：文本先被切分成 token id；相同字符在不同 tokenizer 下的长度、语义边界和成本可能不同。
2. **Causal Transformer**：每个位置只能注意当前及之前的 token，通过 masked self-attention 与 MLP 堆叠预测下一个 token。
3. **自回归生成**：模型输出的是词表上的概率分布；采样策略改变多样性，却不会自动增加知识或可靠性。
4. **上下文窗口**：它是一次请求可处理的 token 范围，不等于模型能可靠利用所有位置，也不等于永久记忆。
5. **KV Cache**：复用历史 token 的 attention key/value，降低逐 token 解码的重复计算，但会占用随序列和并发增长的显存。

### 训练、预训练、微调与迁移学习的层级

```text
训练（所有通过数据更新参数的过程）
├── 预训练：从随机权重建立基础能力，或继续使用自监督目标适配领域
└── 后训练：在基础模型之上塑造可用行为
    ├── 监督微调（SFT）
    └── 偏好对齐（DPO、KTO、PPO 等）

迁移学习（复用已有知识的思想/范式）
├── 特征提取、冻结 backbone、训练任务头
├── 部分解冻、全量微调、PEFT
└── 领域继续预训练
```

| 概念 | 是否相对独立 | 与其他概念的关系 | 能否单独建工程 |
|---|---|---|---|
| 训练 | 否，是总称 | 覆盖预训练、微调和其他参数优化过程 | 通常拆成共享训练基础设施，而非一个业务项目 |
| 预训练 | 是，一个完整生命周期阶段 | 产出基础权重，后续可进入微调和迁移 | 可以，且常因数据/分布式依赖独立 |
| 微调/对齐 | 是，一个后训练阶段 | 微调是迁移学习的常见实现 | 可以，适合独立实验与模型产物目录 |
| 迁移学习 | 不完全是单一阶段 | 它是跨预训练、特征复用、微调的上位范式 | 可以做专项实验，但不应重复建设所有公共组件 |

工程上可以分成独立模块，但要共享数据契约、模型注册、评测集和发布规范。对当前仓库，建议保持 `zero-ai-study` 作为统一实践实验室，在其内部按 `pretraining/`、`fine_tuning/`、`transfer_learning/` 划分实验；只有依赖冲突、算力调度或团队所有权明显不同，再拆成独立仓库。这样既能隔离实验，又不会出现三套重复的数据加载、评测和部署代码。

## 横向：与其他技术的连接

- **与 NLP**：LLM 延续了 tokenization、语言建模、文本生成和语义评测，只是规模与任务统一程度更高。
- **与预训练**：预训练用大规模通用语料学习基础权重，是最昂贵、最底层的能力来源。
- **与迁移学习**：使用预训练模型做特征提取、冻结层或下游微调，本质上是在迁移已学表示。
- **与微调/对齐**：SFT 改变任务行为；DPO 等偏好方法进一步调整回答偏好和边界，但不能保证注入所有实时事实。
- **与 RAG**：检索在推理时提供可更新外部知识，适合私域、时效和可引用信息；它不直接修改模型权重。
- **与 Agent**：Agent 在模型外增加工具、状态和控制循环，适合多步行动；可靠性取决于工作流、权限与观测，而非模型名称。
- **与 CV/多模态**：视觉 encoder、projector 与语言模型连接后形成 VLM，共享 Transformer、对齐和评测基础。
- **与系统工程**：吞吐、首 token 延迟、生成速度、显存、缓存和路由共同决定可用性与成本。

### 生成式 AI 的横向版图

| 模型家族 | 主要生成机制 | 典型模态 | 优势 | 学习优先级 |
|---|---|---|---|---|
| Autoregressive Transformer | 按 token/离散单元逐步预测 | 文本、代码、语音/图像 token | 通用序列建模、LLM 主流 | 主线深入 |
| Diffusion Model | 从噪声逐步去噪 | 图像、视频、音频 | 高质量连续信号生成 | 完成 DL/CV 后扩展 |
| VAE | 概率编码到潜空间再解码 | 图像、表示学习 | 潜空间清晰、训练稳定 | 理解生成建模基础 |
| GAN | 生成器与判别器对抗训练 | 图像、风格迁移 | 采样快、特定任务效果好 | 了解原理与历史地位 |
| Flow/Flow Matching | 学习可逆变换或连续概率路径 | 图像、视频、音频 | 可处理连续生成路径 | 高级生成模型阶段 |

本路线先以 autoregressive LLM 建立第一条纵向闭环；这不代表生成式 AI 只有文本。进入 CV/多模态分支后，应补扩散模型并比较数据表示、训练目标、采样成本和评测方式。

## 技术对比与选型

### 模型架构对比

| 架构 | Attention 可见范围 | 强项 | 典型任务 |
|---|---|---|---|
| Encoder-only | 双向看到完整输入 | 表示、分类、抽取、重排 | BERT 类 NLU/Embedding |
| Decoder-only | 仅看到当前及历史 token | 自回归生成、统一任务接口 | GPT、Llama、Qwen 类 LLM |
| Encoder-Decoder | Encoder 双向，Decoder 因果并 cross-attend | 输入到输出的条件生成 | 翻译、摘要、T5 类任务 |

### 能力适配方式对比

| 方式 | 是否改权重 | 最适合解决 | 优势 | 主要限制 |
|---|---:|---|---|---|
| Prompt/结构化输出 | 否 | 指令、格式、少样本示范 | 成本最低、迭代最快 | 稳定性受模型与上下文影响 |
| RAG | 否 | 私域、实时、可引用知识 | 知识易更新、来源可追踪 | 检索失败会传递给生成 |
| SFT/LoRA | 是 | 固定行为、术语、风格和任务模式 | 可形成稳定任务习惯 | 需高质量数据与回归评测 |
| 偏好对齐 | 是 | 偏好、拒答、回答质量排序 | 优化相对偏好 | 偏好数据偏差会被放大 |
| Agent/Workflow | 通常否 | 工具调用、多步骤业务流程 | 能行动并接入系统 | 权限、状态和失败恢复复杂 |

### 开源模型选型维度

| 维度 | 检查内容 | 不能只看什么 |
|---|---|---|
| 能力 | 目标语言、领域、工具调用、结构化输出 | 综合榜单总分 |
| 许可 | 商用、衍生模型、分发和署名约束 | “开源”两个字 |
| 资源 | 参数量、精度、上下文、KV Cache、并发 | 模型文件大小 |
| 生态 | tokenizer、chat template、推理引擎、量化支持 | 下载量 |
| 风险 | 安全、偏见、隐私、供应链和版本 | 单次 Demo 效果 |

## Step by Step

1. 用 Hugging Face tokenizer 比较中英文、代码、数字和长文本的 token 数，计算上下文与费用影响。
2. 在 PyTorch 中实现一个最小 causal self-attention，验证上三角 mask 后未来位置不可见。
3. 训练一个 tiny decoder language model，记录 loss、困惑度、样例生成和过拟合现象。
4. 使用一个小型开源指令模型，比较 greedy、temperature、top-k 和 top-p，固定 seed 保存结果。
5. 测量不同 prompt 长度、输出长度与并发下的首 token 延迟、生成速度和显存。
6. 为一个私域问答任务建立 Prompt-only、RAG 两条基线，按正确性与引用完整性评估。
7. 阅读 [预训练](../03-训练与适配/09-预训练完整技术路线.md)、[微调与对齐](../03-训练与适配/10-微调与对齐完整技术路线.md) 和 [迁移学习](../03-训练与适配/11-迁移学习完整技术路线.md)，写出选型决策树。
8. 将最佳方案包装为 API，加入超时、日志、敏感信息处理、回归集和回滚版本。

## 最小项目与验收标准

**项目：可评测的领域问答服务**

| 验收项 | 过关标准 |
|---|---|
| 概念 | 能画出 tokenizer -> Transformer -> logits -> sampling 数据流 |
| 基线 | 至少比较 Prompt-only 与 RAG，说明暂不微调或选择微调的依据 |
| 数据 | 文档来源与许可清楚，测试问题不混入调参数据 |
| 评测 | 至少覆盖正确性、引用、拒答、格式与对抗样例 |
| 性能 | 记录 P50/P95、首 token 延迟、输出速度与单请求成本 |
| 工程 | 配置可追溯，服务有超时、日志、健康检查、降级和回滚 |
| 报告 | 明确最好方案、失败类型、适用边界和下一轮实验 |

## 常见误区与面试达标

- 误区：把上下文窗口当成长期记忆，把 Prompt 塞得越长当成效果越好。
- 误区：把 RAG、微调和 Agent 当作互相替代的三个框架；它们解决的是知识、行为和行动控制的不同层次。
- 误区：只测试几条“看起来不错”的回答，不保留固定测试集和失败样本。
- 面试达标：能解释 Q/K/V、causal mask、位置编码、KV Cache 和自回归生成。
- 面试达标：能根据知识时效、行为稳定性、成本和风险，在 Prompt、RAG、微调、Agent 之间做有证据的选择。
