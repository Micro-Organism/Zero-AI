# Python AI 工程师学习路线

> 适合对象：已具备 Java/后端工程经验、有一定 Python 基础，希望转向 Python AI 生态的学习者。

这不是某一个岗位的面试清单，而是一套“基础原理 + 模型训练 + 工程交付 + 方向扩展”的能力体系。默认以 **NLP / LLM / 生成式 AI** 为第一条纵向主线，再逐步扩展 CV、多模态、强化学习、机器人/具身智能和自主系统。

## 快速概览

| 层次 | 要解决的问题 | 核心产出 |
|---|---|---|
| 公共基座 | 能否正确处理数据、实现模型并解释优化过程 | Python 工程、数学、ML、DL、PyTorch |
| LLM 主线 | 能否理解 Transformer，完成训练、微调、评测和推理 | NLP/LLM 实验、微调报告、模型服务 |
| 工程横向 | 模型能否稳定、可观测、可回滚地进入业务 | 数据/模型版本、API、Docker、MLOps、监控 |
| 方向扩展 | 能否把共通能力迁移到视觉、多模态或具身系统 | CV/多模态/RL/机器人选一深入 |

## 学习规则

1. **先完成公共基座，再开分支**：没有 PyTorch 训练与评测能力时，不同时铺 LLM、CV 和机器人三条线。
2. **每个概念必须对应实验**：会说 Attention 不等于会训 Transformer；会调 API 不等于会评估模型。
3. **每个项目留证据**：保留数据版本、基线、参数、指标、失败案例和复现命令。
4. **优先深挖 PyTorch**：TensorFlow、PaddlePaddle、JAX 先做生态识别，不同时深学多套框架。
5. **Java 经验是优势，不是主训练栈**：Python 承载数据、训练与推理；Java 经验用于架构、稳定性、业务集成和团队交付。

## 建议学习顺序

| 阶段 | 主题 | 阶段门禁 |
|---|---|---|
| 1 | Python + 数学 + 数据 | 能写可测试的数据处理包，能解释梯度与概率指标 |
| 2 | ML + 深度学习 + PyTorch | 能从零写训练/验证循环，识别过拟合与数据泄漏 |
| 3 | NLP + Transformer + LLM | 能讲清 Q/K/V、Mask、分词和自回归生成，跑通模型推理 |
| 4 | 预训练原理 + 微调 + 迁移学习 | 能正确选择训练方式，完成微调与评测闭环 |
| 5 | RAG/Agent + 评测 + 部署/MLOps | 能交付有基线、监控、降级和成本指标的 AI 服务 |
| 6 | 分布式/性能 + 一条扩展方向 | 能解释性能瓶颈，完成一个可展示的综合项目 |

详细时间表见 [00-能力地图与学习顺序](./00-能力地图与学习顺序.md)。

遇到不确定归属的模型、算法或框架时，先查 [AI 技术索引](./技术索引.md)。索引给出主章节、关联章节和掌握层级；详细解释以主章节的“核心技术要点与扩展谱系”为准。
