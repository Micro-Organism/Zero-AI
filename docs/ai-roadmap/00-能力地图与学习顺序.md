# AI 工程师能力地图与学习顺序

> 一句话定位：先建立所有 AI 方向共用的底层能力，再用 LLM 做第一条完整纵向，最后选择其他方向扩展。

## 快速概览

| 问题 | 结论 |
|---|---|
| 要不要从 Python 语法开始 | 不逐章重学；用 AI 工程任务反查类型、并发、包管理和测试缺口 |
| 数学要学到什么程度 | 能把公式对应到代码、损失、梯度和指标，不以证明难题为目标 |
| 是否同时学 NLP/CV/机器人 | 前 6 个月不同时深挖；LLM 主线完成后再选分支 |
| 什么叫“学会” | 能独立设计数据分割、基线、训练、评测和服务，并解释失败原因 |

## 起点自评

| 能力 | 过关问题 | 不过关时回到 |
|---|---|---|
| Python | 能否写带类型标注、异常、日志和单测的数据处理包 | `01` |
| 数学 | 能否解释矩阵乘法、链式求导、交叉熵和方差 | `02` |
| ML | 能否设计 train/validation/test，并选对指标 | `03` |
| DL | 能否解释反向传播、学习率、正则化和过拟合 | `04` |
| PyTorch | 能否不借助 Trainer 写出训练/验证/保存循环 | `05` |
| 工程 | 能否用 Git、环境锁定、Docker 和 API 复现一次实验 | `01`、`15` |

## 学习地图（表格）：12 个月主线

> 默认每周 10-15 小时。时间不足时延长阶段，不删减项目与评测环节。

| 阶段 | 月份 | 主学习 | 必做产出 | 过关后进入 |
|---|---:|---|---|---|
| A 公共基座 | 1-2 | Python AI 工程、数学、数据工程、NumPy/Pandas、scikit-learn | 可复现数据流水线 + ML 基线 | B |
| B 深度学习 | 3-4 | 神经网络、PyTorch、GPU、训练诊断 | 一个从零训练的分类模型 + 实验报告 | C |
| C NLP/LLM | 5-6 | 分词、Embedding、Attention、Transformer、HF | 一个 NLP 任务 + 一份 Transformer 原理笔记 | D |
| D 模型后训练 | 7-8 | SFT、LoRA/QLoRA、对齐、评测、导出 | 可复现微调 + 基线对比 + 失败归因 | E |
| E AI 系统 | 9-10 | RAG、Agent、评测、安全治理、FastAPI、Docker、MLOps | 有安全边界、观测性和回归集的 AI 服务 | F |
| F 性能与分支 | 11-12 | 推理优化、分布式概念 + 一条专项 | 作品集项目 + 性能/成本报告 | 求职/研究深入 |

## 核心技术要点与扩展谱系

| 层级 | 技术要点 | 解决的问题 | 前置知识 | 掌握标准 | 关联章节 |
|---|---|---|---|---|---|
| 必会 | Python、SQL、Git、Linux、测试 | 建立可复现工程基座 | 通用编程 | 能独立搭建并验证项目环境 | [01](./01-基础与数据/01-Python与AI工程基础.md)、[19](./01-基础与数据/19-数据工程与特征工程路线.md) |
| 必会 | 数学、ML、DL、PyTorch | 理解并实现训练过程 | 高中数学、Python | 能解释损失、梯度、指标和训练诊断 | `02-05` |
| 必会 | 数据、训练、评测、部署闭环 | 把模型变成可交付系统 | 基础工程能力 | 每个项目都有 baseline、回归和回滚 | `14-15` |
| 进阶 | NLP/LLM、CV、多模态、推荐、时序、语音 | 建立领域专项 | 公共基座 | 任选一条完成纵向闭环 | `06-08`、`13`、`22-24` |
| 进阶 | 预训练、微调、迁移、RAG/Agent | 适配基础模型与外部知识 | Transformer、评测 | 能基于目标与预算正确选型 | `09-12` |
| 了解 | 分布式、具身智能、安全治理、研究复现 | 扩展规模、边界和长期深度 | 一条完整主线 | 能判断进入条件和工程代价 | `16-17`、`20-21` |

## 纵向：每个方向都要闭环

```text
问题定义 -> 数据与合规 -> 基线 -> 模型与训练 -> 离线评测
        -> 误差分析 -> 部署 -> 在线指标 -> 监控/回滚 -> 复盘
```

| 纵向环节 | 必须回答的问题 |
|---|---|
| 问题定义 | 为什么要用 AI？非 AI 基线是什么？ |
| 数据 | 数据从哪里来？是否泄漏、偏置或违规？ |
| 训练 | 只改了哪个变量？如何复现？ |
| 评测 | 指标是否与业务目标一致？失败类型是什么？ |
| 交付 | 延迟、吞吐、成本、安全和回滚如何管理？ |

## 横向：全程穿插的工程能力

| 能力 | 从什么时候开始 | 最低证据 |
|---|---|---|
| Git/依赖/测试 | 第 1 天 | 新环境能按 README 运行，关键函数有测试 |
| 数据版本与质量 | 第 1 个项目 | 数据 schema、统计、校验和训测分离 |
| 实验管理 | 第 1 次训练 | 配置、seed、指标、checkpoint 可追溯 |
| API/容器 | 第 2 个项目 | 健康检查、超时、日志和 Docker 启动 |
| 观测/安全/成本 | 模型服务化后 | 延迟、错误率、token/GPU 成本、敏感数据策略 |
| 技术文档 | 始终 | 问题、方案、对比、结论、限制五段式报告 |

## 技术对比与选型

| 路线 | 第一优先级 | 何时选 | 不应立即选的情况 |
|---|---:|---|---|
| LLM/生成式 AI | 默认主线 | 希望做 NLP、微调、RAG、Agent 和 AI 平台 | 尚不会训练与评测 |
| CV | 第二专项 | 目标是图像分类、检测、分割或工业视觉 | 只是为了“知识面广” |
| 多模态 | LLM+CV 之后 | 已掌握文本和图像至少一侧的完整闭环 | Transformer/Embedding 还没有过关 |
| RL/机器人 | 后期长线 | 愿意补仿真、控制、ROS 2 与硬件 | 只想快速转岗大模型应用 |
| 推荐/时序 | 业务数据分支 | 目标业务有用户-物品交互或连续信号 | 没有可用数据和明确指标 |

## Step by Step

1. 完成起点自评，把不过关项写成清单；已有 Java 能力不重复刷通用语法，只补 Python AI 工程差异。
2. 建立统一 Python 环境、实验目录和报告模板，从 `01` 到 `05` 逐项完成公共基座门禁。
3. 用 NLP 任务进入 Transformer 与 LLM 主线；每学一个概念都保留代码、指标和失败样本。
4. 分清预训练、微调和迁移学习后，完成一次 base vs tuned 的受控微调实验。
5. 把模型接入 RAG/Agent、评测、API、容器和监控，形成第一条可交付系统闭环。
6. 根据目标岗位和兴趣选择 CV/多模态、RL/机器人、推荐、时序或语音之一，不同时深挖全部分支。
7. 用验收表复盘每个项目，整理复现命令、架构图、实验报告、性能成本和已知限制。

## 最小项目与验收标准

| 项目 | 必须包含 | 验收标准 |
|---|---|---|
| ML 基线 | 特征处理、交叉验证、指标、误差分析 | 数据无泄漏，指标选择可解释 |
| PyTorch 项目 | 自定义 Dataset、训练/验证循环、checkpoint | 可从 checkpoint 恢复，有过拟合诊断 |
| LLM 微调 | 数据校验、基线、配置、评测、导出 | 固定评测集上有可复查的改善与退化 |
| AI 服务 | API、超时/重试、监控、Docker、回归集 | 能定位错误，可回滚，可计算成本 |

## 常见误区与面试达标

- **误区：列了框架就算掌握 AI。** 面试要讲数据、基线、指标、失败和取舍。
- **误区：先把所有数学学完再写代码。** 数学应与 NumPy/PyTorch 实验成对学习。
- **误区：用一个 Demo 声称精通。** 达标证据是可复现、可对比、可解释和可交付。
