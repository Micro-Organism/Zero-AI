# 论文阅读与技术跟踪路线

> 一句话定位：围绕具体问题检索、筛选、验证论文证据，并通过最小复现和实验记录判断方法是否值得进入项目。

## 快速概览
| 阶段 | 问题 | 产物 |
|---|---|---|
| 定题 | 当前瓶颈是什么 | problem statement |
| 检索 | 哪些一手资料相关 | paper map |
| 精读 | 假设、方法、证据是什么 | structured notes |
| 复现 | 在什么条件成立 | reproduction report |
| 跟踪 | 后续工作改变了什么 | evidence log |

## 学习地图（表格）
| Step | 主题 | 必做动作 |
|---:|---|---|
| 1 | 问题驱动检索 | 写关键词、同义词和排除条件 |
| 2 | 来源分级 | 论文、代码、文档、博客分层 |
| 3 | 三遍阅读 | 摘要图表 -> 方法 -> 细节 |
| 4 | 证据提取 | 数据、baseline、metric、ablation |
| 5 | 数学/代码映射 | 公式、shape、伪代码、实现对应 |
| 6 | 最小复现 | 固定环境、数据、seed、预期差异 |
| 7 | 批判阅读 | 泄漏、公平性、统计和外推边界 |
| 8 | 技术雷达 | adopt/trial/assess/hold |

## 核心技术要点与扩展谱系

| 层级 | 技术要点 | 解决的问题 | 前置知识 | 掌握标准 | 关联章节 |
|---|---|---|---|---|---|
| 必会 | problem statement、keyword/synonym、citation chain | 从项目问题找到一手工作 | 领域基础 | 能形成候选论文地图 | 全路线 |
| 必会 | three-pass reading、claim-evidence-limit extraction | 高效理解论文主张 | 英文技术阅读 | 能复述假设、方法、证据和限制 | `02`、`14` |
| 必会 | dataset/baseline/metric/ablation/fairness audit | 判断实验是否支持结论 | ML、评测 | 能发现泄漏与不公平比较 | `03`、`14` |
| 必会 | equation -> tensor shape -> pseudocode -> implementation | 将数学映射到代码 | 数学、PyTorch | 能定位核心模块和 loss | `02`、`05` |
| 进阶 | reproduction、environment/seed/commit tracking | 验证主张能否重现 | 工程基础 | 能解释复现差异来源 | `15` |
| 进阶 | controlled ablation、negative result、local baseline | 判断方法是否适合当前项目 | 实验设计 | 能给出采用/暂缓证据 | `14` |
| 必会 | source hierarchy、license/code maintenance、technology radar | 持续跟踪而不追热点 | 信息检索 | 能维护 adopt/trial/assess/hold | `18` |

## 纵向：从原理到交付的完整闭环
```text
项目瓶颈 -> survey/引用链检索 -> 候选筛选 -> 三遍阅读
         -> 假设/方法/证据表 -> 官方代码核对 -> 最小复现
         -> 本地 baseline 对比 -> 采用/暂缓决策 -> 持续更新
```
| 阅读层 | 关注 | 停止条件 |
|---|---|---|
| 第一遍 | 问题、结论、图表、成本 | 与目标无关则归档 |
| 第二遍 | 方法、数据、baseline、指标 | 证据不足则降级 |
| 第三遍 | 公式、实现、消融、限制 | 足够复现关键主张 |

## 横向：与其他技术的连接
- **与数学**：公式要落到 tensor shape、损失和梯度，不孤立推导。
- **与工程**：官方代码可运行不等于项目可采用，还需许可证、成本和维护性。
- **与评测**：复现必须使用同一 baseline、数据和统计方法。
- **与求职**：一篇高质量复现报告比“读过 100 篇论文”更可信。
- **与前沿跟踪**：优先一手论文、官方代码和变更日志，博客只用于导航。

## 技术对比与选型
| 来源 | 优势 | 风险 | 用法 |
|---|---|---|---|
| 论文 | 方法与实验较完整 | 可能过时/选择性报告 | 核对主张与限制 |
| 官方代码 | 最接近实现 | 环境复杂、实现偏离论文 | 复现和 shape 跟踪 |
| 官方文档 | 当前接口可靠 | 少解释研究取舍 | 工程落地 |
| Survey | 快速建立地图 | 滞后、二手归纳 | 找术语和引用链 |
| Blog/社媒 | 易发现趋势 | 夸大、缺证据 | 只作线索 |

## Step by Step
1. 从当前项目写一个可测量瓶颈，不以“最近什么火”开题。
2. 找一篇 survey/经典工作和 3-5 篇关键后续论文，画引用关系。
3. 用统一模板记录假设、数据、模型、指标、成本、结果和限制。
4. 对照官方代码定位核心模块、损失和默认超参数。
5. 先复现最小主张，再做一个关键消融和一个失败条件。
6. 与项目现有 baseline 在同一数据/预算下比较。
7. 写 adopt/trial/assess/hold 决策及证据强度。
8. 每月只更新与主线/专项有关的技术雷达。

## 最小项目与验收标准
**项目：一篇论文的最小复现与采用决策**
| 验收项 | 过关标准 |
|---|---|
| 来源 | 论文、版本、代码 commit、许可明确 |
| 理解 | 能讲假设、方法、shape、损失和限制 |
| 复现 | 环境、seed、数据和结果可追溯 |
| 对比 | 同预算 baseline、消融和失败案例完整 |
| 决策 | 说明是否采用及质量/成本/复杂度取舍 |

## 常见误区与面试达标
- 误区：只读摘要和二手解读，或不看 baseline 公平性。
- 误区：复现不出来就调到成功，却不记录偏差来源。
- 面试达标：能从论文主张追到实验、代码和本地证据。
