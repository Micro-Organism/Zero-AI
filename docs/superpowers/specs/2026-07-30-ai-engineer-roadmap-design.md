# AI Engineer Roadmap Design

## Goal

为已具备 Java 工程能力、有一定 Python 基础的学习者，在本仓库内建立一套以 Python 生态为主的 AI 工程师学习体系。它不以任何一条 JD 为边界，而是以共通基础、大模型主线、算法工程化和多方向扩展为结构。

## 定位与边界

- **目标形象**：能独立完成数据、模型、训练、评测、推理服务与业务集成闭环的 Python AI 工程师，并能与 Java 业务系统协作。
- **主线**：NLP / LLM / 生成式 AI 及算法工程化。
- **扩展方向**：CV、多模态、强化学习、机器人/具身智能、推荐与时序。它们在共同基础完成后再按兴趣和岗位选一条深入，不与 LLM 主线同时深挖。
- **不追求**：用教程复制论文、从零预训练中大型 LLM 或在第一阶段掌握所有 AI 子领域。

## 学习架构

```text
公共基座: Python -> 数学 -> 数据 -> 机器学习 -> 深度学习 -> PyTorch
                                           |
LLM 主线: NLP -> Transformer -> 生成式 AI -> 预训练 -> 微调/对齐 -> 评测 -> 推理
                                           |
工程横向: 数据工程 -> API/服务 -> 容器 -> MLOps -> 分布式 -> 性能优化
                                           |
方向扩展: CV/多模态 | 强化学习/机器人 | 推荐/时序
```

“纵向”指一个题目从原理、数据、训练到评测和部署的完整闭环；“横向”指跨题目复用的工程能力，例如版本管理、数据质量、可观测性、安全与成本管理。

## 目录与文档责任

在 `docs/ai-roadmap/` 下建立以下层次：

| 类别 | 文件 | 责任 |
|------|------|------|
| 导航 | `README.md` | 总览、学习规则、入口与阶段产出 |
| 导航 | `00-能力地图与学习顺序.md` | 12 个月分阶段规划、前置依赖与选择节点 |
| 基础 | `01` 至 `05` | Python 工程、数学、ML、深度学习、PyTorch |
| 主线 | `06` 至 `12` | NLP、CV、LLM、预训练、微调、迁移学习、RAG/Agent |
| 工程 | `13` 至 `16` | 多模态、评测与算法工程、部署/MLOps、分布式与性能 |
| 扩展 | `17` | 强化学习与机器人/具身智能 |
| 产出 | `18` | 作品集、开源、简历和面试闭环 |

每篇专题文档采用同一模板：

1. 这个领域解决什么问题，与其他领域的关系。
2. 学习前置、必备知识点和横向能力。
3. 纵向完整流程：数据 -> 模型 -> 训练 -> 评测 -> 部署。
4. Python 主工具栈、必做实验和最小项目。
5. 验收标准、常见误区、面试表达与后续分支。

## 与现有内容的关系

- `zero-ai-study/` 继续作为“微调实操实验室”，不移动、不重复写其已有步骤。
- `docs/02-微调学习计划.md` 继续作为 LLaMA Factory 与微调框架选型参考，补充指向新路线中的微调专题。
- 新文档只提供路径、练习和验收标准；当一个项目有明确实作范围时，再在 `zero-ai-study/` 或独立实验仓建立代码。

## 实施批次

1. 创建路线索引、能力地图和基础阶段文档。
2. 创建 LLM 主线和预训练/微调/迁移学习三篇纵向专题。
3. 创建算法工程化、MLOps、分布式和性能优化专题。
4. 创建 CV、多模态、强化学习/机器人扩展专题。
5. 更新现有微调和推荐阅读文档的交叉链接，并进行链接校验。

## 成功标准

- 使用者能从 `docs/ai-roadmap/README.md` 得知今天应学什么、为什么学和达到什么标准才能继续。
- 微调、预训练和迁移学习被清楚区分，同时在同一个 AI 模型生命周期中定位。
- 文档提供共通主线与后期方向选择，不将单一公司的 JD 写成学习上限。
- 每个阶段均有可操作的产出或验收门槛，而不只是技术名词清单。
