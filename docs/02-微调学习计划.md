## LLaMA Factory 是什么

**LLaMA Factory（项目名通常写作 LlamaFactory）**是一个开源、一站式大语言模型微调平台。它将模型加载、数据模板、训练、对齐、评估、导出和推理等步骤统一在一套配置和命令中，并提供 Gradio WebUI。

可以把它理解为大模型微调的“集成工作台”：它并不取代 PyTorch、Transformers、PEFT 或 TRL，而是把这些底层能力组装成更易使用的端到端流程。

### 核心能力

1. **模型覆盖广**：适配 Llama、Qwen、DeepSeek、Gemma、ChatGLM、Baichuan、Yi 及多模态模型等主流开源模型家族。
2. **训练方式完整**：支持增量预训练、SFT、全参数微调、冻结微调和 LoRA/QLoRA 等参数高效微调。
3. **偏好对齐**：覆盖 DPO、KTO、ORPO、PPO 等常见对齐方法，具体可用算法需以当前版本文档为准。
4. **低代码门槛**：同时提供命令行、YAML 配置和 Gradio WebUI，方便新手入门和快速试验。
5. **训练加速与多卡**：可集成 FlashAttention、DeepSpeed、FSDP 等能力，并可按版本接入 Unsloth 等加速方案。
6. **产物处理**：支持适配器保存、模型合并、量化、评估和推理部署相关流程。

### 适合人群

- 刚开始学习大模型微调，希望先通过 WebUI 跑通流程的开发者
- 需要快速对比多种模型、数据模板和训练方案的团队
- 希望用统一工具完成 SFT、偏好对齐、导出和推理验证的开发者

## 同类主流工具

> 下列项目与 LLaMA Factory 有较大功能交集，但定位并不完全相同：有的偏端到端平台，有的偏训练配方、性能优化或学术研究。

### 1. Unsloth

- **定位**：以低显存和高速训练为核心的微调与推理工具。
- **优势**：对 LoRA/QLoRA 和消费级 GPU 优化较深；提供大量 Kaggle/Colab Notebook；支持导出 GGUF 等常用格式。
- **限制**：它的主要价值是性能优化，模型与分布式能力覆盖会随版本、硬件和功能层级变化。
- **适用**：单卡或显存紧张环境下快速迭代。本仓库当前就采用这条路线。

### 2. Axolotl

- **定位**：以 YAML 配置驱动的微调和对齐框架。
- **优势**：实验配置易于版本管理和复现；示例配置丰富；对 DeepSpeed、FSDP 等多卡方案支持较完整。
- **限制**：主要通过配置和命令行使用，需要先理解数据格式和训练参数。
- **适用**：实验室、企业训练平台和强调可复现性的团队。

### 3. ms-swift（ModelScope Swift）

- **定位**：阿里 ModelScope 生态中的训练、对齐、评估、量化和部署工具链。
- **优势**：对 Qwen 系列、中文数据和多模态模型适配积极；兼顾训练与推理部署；国内文档和示例便于使用。
- **限制**：功能面较广，配置项和版本差异需要结合官方文档理解。
- **适用**：主要使用 Qwen、ModelScope 模型或中文多模态场景的团队。

### 4. XTuner

- **定位**：由 InternLM 生态推动的高效大模型微调工具。
- **优势**：对 InternLM 系列和常见开源模型有现成配置；支持 LoRA/QLoRA、全参数微调及分布式训练。
- **限制**：模型和训练范式的整体覆盖度通常不如大型综合平台。
- **适用**：InternLM 生态用户，以及希望用配置化方式完成高效微调的开发者。

### 5. TorchTune

- **定位**：PyTorch 官方生态的原生大模型微调库与训练配方集。
- **优势**：组件化、训练逻辑相对透明，便于研究 PyTorch 原生训练流程和做底层定制。
- **限制**：不以 WebUI 和最广模型覆盖为核心，使用者需要更熟悉 PyTorch 和训练原理。
- **适用**：算法研究、训练循环定制和 PyTorch 原生技术栈。

### 6. LMFlow

- **定位**：面向学术研究的大模型训练、对齐和评估工具链。
- **优势**：覆盖从指令微调到人类偏好对齐的完整概念链路，适合阅读代码和学习方法。
- **限制**：在模型适配广度、开箱即用体验和社区活跃度上，需要先评估是否符合当前项目。
- **适用**：微调与 RLHF/偏好对齐原理学习、学术实验。

### 7. Firefly（流萤）

- **定位**：面向中文大模型的训练工具和配置集。
- **优势**：对中文指令数据、对话模板和国产开源模型有较多实践样例，支持全参数及 LoRA/QLoRA 等训练方式。
- **限制**：更偏中文生态，选型前应检查目标模型、对齐算法和分布式训练的当前支持情况。
- **适用**：中文垂直领域微调和国产模型实验。

## 与底层库的区别

TRL 和 PEFT 经常被上述工具调用，但它们的定位更偏底层能力，不宜与 LLaMA Factory 简单地当作同一层级的竞品。

| 库 | 定位 | 典型用途 |
|----|------|----------|
| **PEFT** | Hugging Face 参数高效微调库 | LoRA、AdaLoRA、Prefix Tuning 等适配器方法 |
| **TRL** | Hugging Face 后训练与偏好对齐库 | SFT、DPO、PPO、GRPO 等训练器和算法实现 |

关系可简化为：

```text
LLaMA Factory / Axolotl / ms-swift 等端到端工具
                ↓ 组装或调用
Transformers + PEFT + TRL + PyTorch + DeepSpeed/FSDP 等底层组件
```

## 快速选型建议

1. **零基础，想先用可视化界面跑通流程**：优先 LLaMA Factory。
2. **只有一张消费级 GPU，显存小且追求迭代速度**：优先 Unsloth。
3. **强调 YAML 配置、Git 管理和实验复现**：优先 Axolotl。
4. **主要使用 Qwen、ModelScope 或中文多模态模型**：优先 ms-swift。
5. **主要使用 InternLM**：优先 XTuner。
6. **想深入理解 PyTorch 训练循环并做底层定制**：优先 TorchTune。
7. **想研究微调、RLHF 和偏好对齐的完整流程**：可评估 LMFlow，并直接学习 TRL。

### 对本学习项目的建议

当前 `zero-ai-study` 已经围绕 **Unsloth + QLoRA + SFT** 建立完整实操链路，没有必要为了试工具立即切换主框架。建议先完成当前的 Step 9 工程闭环，再用同一份小数据集在 LLaMA Factory 中复现一次 SFT，对比两者的数据配置、显存、训练时间、日志和导出产物。这样能学到选型方法，而不只是更换命令。

## 使用时的注意事项

- 模型数量、加速倍数、显存节省比例、多卡限制和 WebUI 能力都可能随版本快速变化，不应把某一时点的宣传数字当作长期结论。
- 性能取决于模型、序列长度、batch size、量化方式、GPU 型号和软件版本，选型时应用自己的数据做小规模基准测试。
- 开源许可证、商业功能边界和模型权重许可是三件不同的事；商用前应分别检查工具代码、依赖和基座模型的当前许可条款。
